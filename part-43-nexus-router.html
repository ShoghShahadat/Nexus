مستندات پروژه-محور Nexus

بخش ۴۳: ادغام با GoRouter با پکیج nexus_router

چگونه برای هر صفحه، یک دنیای Nexus مستقل داشته باشیم و ناوبری را به صورت تمیز مدیریت کنیم.

هر صفحه، یک دنیا

در اپلیکیشن‌های تک-صفحه‌ای (Single Page Applications) مانند `nexus_layout_kit`، ما یک `NexusWorld` برای کل برنامه داریم. اما در بسیاری از اپلیکیشن‌ها، هر صفحه (route) منطق و وضعیت کاملاً مستقلی دارد. مدیریت تمام این منطق‌ها در یک دنیای واحد می‌تواند منجر به پیچیدگی شود.

یک الگوی قدرتمند، در نظر گرفتن هر صفحه به عنوان یک "صحنه" یا "دنیای" Nexus مستقل است. پکیج `nexus_router` یک ابزار کمکی است که این الگو را با استفاده از پکیج محبوب `go_router` بسیار ساده می‌کند.

فلسفه وجودی `NexusRoute`

`NexusRoute` یک کلاس است که از `GoRoute` ارث‌بری می‌کند. این کلاس، تمام boilerplate مربوط به راه‌اندازی یک `NexusWidget` برای یک روت خاص را در خود کپسوله می‌کند. شما به جای تعریف یک `builder` پیچیده، فقط دو تابع اصلی را ارائه می‌دهید:

  • `worldProvider`: تابعی که دنیای Nexus مخصوص این صفحه را می‌سازد. این تابع در ایزولیت منطق اجرا می‌شود.
  • `renderingSystemBuilder`: تابعی که سیستم رندرینگ مخصوص این صفحه را می‌سازد. این تابع در ترد UI اجرا می‌شود.

مثال عملی: اپلیکیشن با دو صفحه

تصور کنید اپلیکیشنی با دو صفحه داریم: یک صفحه اصلی و یک صفحه بازی. 


// router.dart

import 'package:go_router/go_router.dart';
import 'package:nexus_router/nexus_router.dart';

// دنیای مربوط به صفحه اصلی
NexusWorld createHomeWorld() {
  final world = NexusWorld();
  world.loadModule(HomeModule());
  return world;
}

// دنیای مربوط به صفحه بازی
NexusWorld createGameWorld() {
  final world = NexusWorld();
  world.loadModule(GameModule());
  return world;
}

final router = GoRouter(
  routes: [
    // روت صفحه اصلی
    NexusRoute(
      path: '/',
      worldProvider: createHomeWorld,
      renderingSystemBuilder: (context) => HomeRenderingSystem(),
    ),
    // روت صفحه بازی
    NexusRoute(
      path: '/game',
      worldProvider: createGameWorld,
      renderingSystemBuilder: (context) => GameRenderingSystem(),
    ),
  ],
);

به همین سادگی! وقتی کاربر به آدرس `/game` می‌رود، `NexusRoute` به طور خودکار:

  1. یک `NexusWidget` جدید می‌سازد.
  2. یک ایزولیت جدید برای `gameWorld` ایجاد می‌کند.
  3. `GameRenderingSystem` را به آن متصل می‌کند.

و مهم‌تر از همه، وقتی کاربر از این صفحه خارج می‌شود، `NexusWidget` از بین رفته و متد `dispose` آن فراخوانی می‌شود، که به طور خودکار کل `gameWorld` و ایزولیت آن را از حافظه پاک می‌کند.

مزایای این الگو

  • ایزولاسیون کامل صفحات: منطق و وضعیت هر صفحه کاملاً از صفحات دیگر جداست. یک کرش در دنیای بازی، هیچ تأثیری بر صفحه اصلی ندارد.
  • مدیریت خودکار حافظه: شما نگران پاک کردن وضعیت یک صفحه پس از خروج از آن نیستید. `NexusRoute` این کار را به صورت خودکار انجام می‌دهد.
  • کد تمیز و اعلامی: تعریف روت‌ها بسیار خوانا و ساده می‌شود. شما فقط "چه چیزی" (کدام دنیا و کدام سیستم رندرینگ) را مشخص می‌کنید، نه "چگونه" (نحوه ساخت ویجت و مدیریت ایزولیت).
