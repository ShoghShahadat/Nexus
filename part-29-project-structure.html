مستندات پروژه-محور Nexus

بخش ۲۹: ساختار پیشنهادی پروژه

یک نقشه راه عملی برای سازماندهی فایل‌ها و پوشه‌ها در یک پروژه بزرگ مبتنی بر Nexus.

یک خانه مرتب

یک معماری خوب به تنهایی کافی نیست. داشتن یک ساختار پوشه تمیز، قابل پیش‌بینی و مقیاس‌پذیر به همان اندازه اهمیت دارد. این کار به اعضای جدید تیم کمک می‌کند تا به سرعت با پروژه آشنا شوند و پیدا کردن کدها را برای همه آسان‌تر می‌کند.

در این بخش، ما یک ساختار پوشه پیشنهادی را که بر اساس اصول ماژولاریتی Nexus طراحی شده، بررسی می‌کنیم. این ساختار همان چیزی است که در پروژه `nexus_layout_kit` نیز (تا حد زیادی) رعایت شده است.

ساختار سطح بالای `lib`


lib/
|-- main.dart           # نقطه ورود اصلی اپلیکیشن
|-- bootstrap.dart      # مسئولیت ثبت سرویس‌ها و کامپوننت‌ها
|-- src/                # تمام کدهای اصلی اپلیکیشن در اینجا قرار دارند
|   |-- core/           # مفاهیم اصلی و پایه‌ای اپلیکیشن (اختیاری)
|   |-- features/       # **مهم‌ترین پوشه**: هر ویژگی یک زیرپوشه در اینجا دارد
|   |-- services/       # پیاده‌سازی سرویس‌های خارجی (مانند شبکه)
|   |-- shared/         # ماژول اشتراکی (SharedModule)
|   `-- ui/             # ویجت‌های عمومی و تم برنامه
`-- nexus_app.dart      # تعریف NexusApp و خط لوله رندرینگ

غواصی در پوشه `features`

قلب تپنده این ساختار، پوشه `features` است. هر زیرپوشه در اینجا، یک ماژول مستقل و کامل است. بیایید ساختار داخلی یکی از این ماژول‌ها، مثلا `profile`، را بررسی کنیم. 


features/
|-- profile/
|   |-- components/     # تعریف کامپوننت‌های مخصوص این ماژول
|   |   `-- profile_data_component.dart
|   |
|   |-- systems/        # تعریف سیستم‌های مخصوص این ماژول
|   |   `-- profile_system.dart
|   |
|   |-- ui/             # تمام کدهای مربوط به UI این ماژول
|   |   |-- builders/   # بیلدرهای IWidgetBuilder
|   |   |   `-- profile_panel_builder.dart
|   |   |
|   |   `-- widgets/    # ویجت‌های کوچک و قابل استفاده مجدد
|   |       `-- profile_card_widget.dart
|   |
|   `-- profile_module.dart # نقطه ورود ماژول که اجزا را مونتاژ می‌کند

توضیح اجزا:

  • `profile_module.dart`: این فایل کلاس `ProfileModule` را تعریف می‌کند. این کلاس مسئولیت دارد که تمام `SystemProvider`ها و `EntityProvider`های مربوط به این ویژگی را مونتاژ کند.
  • پوشه `components`: تمام کامپوننت‌های داده‌ای که فقط و فقط در این ماژول استفاده می‌شوند، در اینجا قرار می‌گیرند.
  • پوشه `systems`: تمام سیستم‌هایی که منطق این ویژگی را پیاده‌سازی می‌کنند.
  • پوشه `ui`: این پوشه خود به دو بخش تقسیم می‌شود:
    • `builders`: بیلدرهای اصلی و سطح بالای `IWidgetBuilder` که مسئولیت رندر کردن صفحات یا پنل‌های کامل را بر عهده دارند.
    • `widgets`: ویجت‌های استاندارد و کوچک فلاتر که توسط بیلدرها استفاده می‌شوند.

مزایای این ساختار

  • قابلیت کشف بالا (High Discoverability): اگر می‌خواهید روی ویژگی پروفایل کار کنید، می‌دانید که تمام کدهای مرتبط در `features/profile` قرار دارند.
  • کپسوله‌سازی قوی: تمام جزئیات پیاده‌سازی یک ویژگی در داخل پوشه آن پنهان شده است.
  • مقیاس‌پذیری: افزودن یک ویژگی جدید به سادگی ایجاد یک پوشه جدید در `features` است.
