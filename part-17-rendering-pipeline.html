مستندات پروژه-محور Nexus

بخش ۱۷: بازنگری خط لوله رندرینگ

نگاهی عمیق‌تر به نحوه ساخت UI از پایه و ترکیب بیلدرها در `nexus_layout_kit`.

از `NexusApp` تا پیکسل‌ها

در بخش ۵، ما یک نمای کلی از پل میان منطق و UI را دیدیم. در این بخش، ما به فایل `main.dart` پروژه `nexus_layout_kit` بازمی‌گردیم تا این خط لوله را به صورت عملی و با جزئیات بیشتری بررسی کنیم. هدف این است که بفهمیم چگونه یک ساختار درختی از ویجت‌ها با استفاده از بیلدرهای ماژولار ساخته می‌شود.

نقطه شروع: `NexusApp` و `rootBuilder`

همه چیز از ویجت `NexusApp` شروع می‌شود. ما قبلاً با پراپرتی `worldProvider` آن آشنا شدیم. پراپرتی کلیدی دیگر، `rootBuilder` است. این پراپرتی، اولین `IWidgetBuilder` در زنجیره رندرینگ را مشخص می‌کند. این بیلدر مسئول ساخت ویجت ریشه اپلیکیشن، یعنی `Scaffold`، است. 


// File: lib/main.dart

return NexusApp(
  worldProvider: worldProvider,
  rootBuilder: scaffoldBuilder, // نقطه شروع رندرینگ UI
  theme: ThemeData(...),
);

`ScaffoldBuilder`: اسکلت اصلی UI

متغیر `scaffoldBuilder` یک نمونه از کلاس `ScaffoldBuilder` است. این کلاس یک `IWidgetBuilder` است که مسئولیت ساخت `Scaffold` و ترکیب بخش‌های اصلی UI (AppBar, Drawer, Body) را بر عهده دارد. 


// File: lib/main.dart

final scaffoldBuilder = ScaffoldBuilder(
  appBarBuilder: AppBarBuilder(),
  appBarEntityTag: BuilderTags.appBar, // تگ برای پیدا کردن موجودیت AppBar
  
  drawerBuilder: NavigationPanelBuilder(),
  drawerEntityTag: BuilderTags.navigationPanel, // تگ برای پیدا کردن موجودیت منو
  
  bodyBuilder: bodyBuilder, // یک بیلدر دیگر که در ادامه می‌بینیم
  bodyEntityTag: BuilderTags.body, // تگ برای پیدا کردن موجودیت بدنه
);

`ScaffoldBuilder` در متد `build` خود، با استفاده از تگ‌های ارائه شده، شناسه‌های موجودیت‌های مربوط به AppBar، Drawer و Body را از `FlutterRenderingSystem` پیدا می‌کند. سپس، بیلدر مربوط به هر بخش را فراخوانی کرده و ویجت‌های خروجی آن‌ها را در مکان‌های مناسب `Scaffold` قرار می‌دهد.

`BodyBuilder`: ترکیب محتوای پویا

جذاب‌ترین بخش این ساختار، `bodyBuilder` است. این بیلدر خود یک ترکیب‌کننده است. `BodyBuilder` مسئولیت دارد که بر اساس وضعیت فعلی، تصمیم بگیرد کدام پنل محتوایی باید در بدنه اصلی صفحه نمایش داده شود. 


// File: lib/main.dart

final bodyBuilder = BodyBuilder(
  contentBuilders: {
    // یک نقشه از نوع محتوا به بیلدر مربوطه‌اش
    BodyContentType.categories: CategoryPanelBuilder(),
    BodyContentType.settings: SettingsPanelBuilder(),
    BodyContentType.buttonsShowcase: ButtonsShowcasePanelBuilder(...),
    BodyContentType.profile: profilePanelBuilder, // این خودش یک بیلدر ترکیبی است!
  },
);

`BodyBuilder` به کامپوننت `BodyStateComponent` در موجودیت `body` گوش می‌دهد. این کامپوننت یک `enum` به نام `BodyContentType` را در خود دارد. `BodyBuilder` از مقدار این `enum` به عنوان کلید برای پیدا کردن بیلدر مناسب از نقشه `contentBuilders` استفاده کرده و سپس متد `build` آن بیلدر را فراخوانی می‌کند.

`StateWidgetAssembler`: اوج ترکیب‌پذیری

همانطور که در بخش ۷ دیدیم، `profilePanelBuilder` خود یک `StateWidgetAssembler` است. این یعنی ما می‌توانیم بیلدرها را مانند لگو روی هم بچینیم:

  • `ScaffoldBuilder` از `BodyBuilder` استفاده می‌کند.
  • `BodyBuilder` بر اساس وضعیت، ممکن است از `StateWidgetAssembler` (برای پروفایل) استفاده کند.
  • `StateWidgetAssembler` بر اساس وضعیت پروفایل، یکی از `Profile...StateBuilder` ها را انتخاب می‌کند.

الگوی طراحی ترکیبی (Composite Pattern)

این ساختار درختی از بیلدرها، یک پیاده‌سازی زیبا از الگوی طراحی ترکیبی است. این الگو به ما اجازه می‌دهد تا با اشیاء ساده (بیلدرهای منفرد) و ترکیبی (بیلدرهایی که از بیلدرهای دیگر استفاده می‌کنند) به صورت یکسان رفتار کنیم. نتیجه، یک کد بسیار ماژولار، انعطاف‌پذیر و قابل توسعه است.

این بخش، پایان سفر ما در مفاهیم اصلی Nexus بود. شما اکنون با تمام قطعات اصلی این فریم‌ورک قدرتمند، از تعریف داده تا منطق و رندرینگ، آشنا شده‌اید.
