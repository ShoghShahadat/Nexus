مستندات پروژه-محور Nexus

بخش ۲۲: سرویس‌ها و تزریق وابستگی با GetIt

چگونه وابستگی‌های خارجی مانند سرویس‌های شبکه یا پایگاه داده را در معماری Nexus مدیریت کنیم.

فراتر از دنیای ECS

معماری ECS برای مدیریت وضعیت و منطق داخلی اپلیکیشن فوق‌العاده است. اما هر اپلیکیشن واقعی نیاز به تعامل با دنیای خارج دارد: تماس با APIهای وب، خواندن و نوشتن در پایگاه داده، دسترسی به سنسورهای دستگاه و غیره. این وابستگی‌های خارجی "سرویس" نامیده می‌شوند.

سوال این است: چگونه این سرویس‌ها را به سیستم‌های خود که در دنیای ایزوله Nexus زندگی می‌کنند، برسانیم؟ پاسخ، استفاده از یک الگوی قدرتمند به نام تزریق وابستگی (Dependency Injection) است.

ادغام با `GetIt`: سرویس لوکیتور

فریم‌ورک Nexus به صورت پیش‌فرض با پکیج محبوب `get_it` ادغام شده است. `GetIt` یک سرویس لوکیتور (Service Locator) ساده است که به شما اجازه می‌دهد تا نمونه‌های سرویس‌های خود را در یک مکان مرکزی "ثبت" کنید و سپس از هر جای دیگر در برنامه، آن‌ها را "دریافت" نمایید.

هر `NexusWorld` یک نمونه از `GetIt` را در خود دارد که از طریق پراپرتی `services` قابل دسترسی است.

الگوی کار با سرویس‌ها در Nexus

بهترین روش برای کار با سرویس‌ها در Nexus به این صورت است:

  1. تعریف یک اینترفیس (Abstract Class): همیشه با تعریف یک قرارداد (اینترفیس) برای سرویس خود شروع کنید. این کار سیستم شما را از پیاده‌سازی واقعی سرویس جدا می‌کند و تست‌پذیری را به شدت افزایش می‌دهد.
  2. پیاده‌سازی اینترفیس: یک کلاس مشخص بسازید که اینترفیس را پیاده‌سازی می‌کند. این کلاس می‌تواند از پکیج‌هایی مانند `Dio` یا `http` استفاده کند.
  3. ثبت سرویس در `GetIt`: در نقطه شروع برنامه (معمولاً در `main.dart` یا یک فایل `bootstrap`), نمونه‌ای از کلاس پیاده‌سازی شده را در `GetIt` ثبت کنید.
  4. دریافت و استفاده در سیستم: در متد `init` یا `onAddedToWorld` سیستم خود، سرویس را از طریق `services.get()` دریافت کرده و از آن استفاده کنید.

مثال عملی: `INetworkService`

پکیج `nexus` خود این الگو را برای سرویس‌های شبکه پیاده‌سازی کرده است. 


// 1. تعریف اینترفیس در پکیج nexus
// File: lib/src/services/network/i_network_service.dart

abstract class INetworkService {
  Future> request(String url, {required HttpMethod method, ...});
}

// 2. پیاده‌سازی اینترفیس در اپلیکیشن شما
class DioNetworkService implements INetworkService {
  final Dio _dio = Dio();
  
  @override
  Future> request(...) {
    // ... منطق ارسال درخواست با Dio
  }
}

// 3. ثبت سرویس در main.dart
void main() {
  GetIt.I.registerSingleton(DioNetworkService());
  // ...
  runApp(const MyApp());
}

// 4. استفاده در ApiSystem
// File: lib/src/systems/api_system.dart

class ApiSystem extends System {
  late final INetworkService _networkService;

  @override
  Future init() async {
    // سیستم، سرویس را از GetIt درخواست می‌کند
    _networkService = services.get();
  }
  
  @override
  void update(Entity entity, double dt) async {
    // ...
    final responseJson = await _networkService.request(...);
    // ...
  }
}

چرا این الگو مهم است؟

با تعریف اینترفیس، `ApiSystem` هیچ اطلاعی از وجود پکیج `Dio` ندارد. این یعنی شما می‌توانید فردا به راحتی `DioNetworkService` را با `HttpNetworkService` جایگزین کنید، بدون اینکه نیاز به تغییر حتی یک خط کد در `ApiSystem` داشته باشید. همچنین، در تست‌ها می‌توانید یک `MockNetworkService` به سیستم تزریق کنید تا پاسخ‌های جعلی را برای تست کردن منطق سیستم، شبیه‌سازی نمایید.
