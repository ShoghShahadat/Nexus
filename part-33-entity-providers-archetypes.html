مستندات پروژه-محور Nexus

بخش ۳۳: آرکیتایپ‌ها و ساخت موجودیت

استفاده از الگوهای آماده (Prefabs) برای ساخت موجودیت‌های پیچیده به روشی تمیز و قابل استفاده مجدد.

مشکل: تکرار در ساخت موجودیت

وقتی اپلیکیشن شما بزرگ می‌شود، ممکن است نیاز داشته باشید که انواع مختلفی از یک "چیز" را بسازید. برای مثال در یک بازی، ممکن است چندین نوع دشمن داشته باشید: یک گابلین ساده، یک گابلین کماندار، و یک گابلین فرمانده. همه این‌ها "گابلین" هستند و ویژگی‌های مشترکی دارند، اما تفاوت‌هایی هم دارند.

نوشتن کد برای ساخت هر کدام از این‌ها به صورت جداگانه، منجر به تکرار کد و دشواری در نگهداری می‌شود.

راه حل: آرکیتایپ‌ها (Archetypes)

Nexus یک کلاس به نام `Archetype` ارائه می‌دهد که به عنوان یک "الگوی آماده" یا "Prefab" عمل می‌کند. یک آرکیتایپ، مجموعه‌ای از کامپوننت‌های از پیش تعریف شده است که یک نوع موجودیت را توصیف می‌کند. 


// از پکیج nexus

class Archetype {
  final List _components;
  Archetype(this._components);
  void apply(Entity entity) { /* ... */ }
}

// تعریف یک آرکیتایپ پایه برای همه گابلین‌ها
final goblinArchetype = Archetype([
  HealthComponent(maxHealth: 50),
  MovementComponent(speed: 2.0),
  TagsComponent({'enemy', 'goblin'}),
  LifecyclePolicyComponent(...)
]);

// تعریف آرکیتایپ برای کماندار، که ویژگی‌های پایه را گسترش می‌دهد
final archerArchetype = Archetype([
  ...goblinArchetype._components, // گسترش آرکیتایپ پایه
  CanShootComponent(damage: 10, range: 100),
]);

`EntityProvider` و `EntityAssembler`

`EntityProvider` کلاسی است که در زمان بارگذاری ماژول، مسئولیت ساخت موجودیت‌های اولیه را بر عهده دارد. برای منطق‌های پیچیده‌تر ساخت موجودیت، می‌توان از `EntityAssembler` استفاده کرد که یک الگوی سطح بالاتر برای مونتاژ موجودیت‌ها از روی آرکیتایپ‌ها و سایر منابع داده است. 


// File: lib/src/components_showcase/buttons/buttons_entity_provider.dart

class ButtonsEntityProvider extends EntityProvider {
  @override
  void createEntities(NexusWorld world) {
    // این تابع یک "اسمبلر" داخلی است
    Entity createButton(String id, String label, List components) {
      final entity = Entity()
        ..add(TagsComponent({'button_showcase_item'}))
        ..add(ButtonComponent(id: id, label: label))
        ..addComponents(components) // ترکیب کامپوننت‌های پایه و سفارشی
        ..add(LifecyclePolicyComponent(isPersistent: true));
      world.addEntity(entity);
      return entity;
    }

    // استفاده از اسمبلر برای ساخت دکمه‌های مختلف با حداقل تکرار
    createButton('contained_primary', 'Primary', [
      ButtonStyleComponent(ButtonVariant.contained),
      ButtonColorComponent(ButtonColor.primary)
    ]);
    createButton('contained_secondary', 'Secondary', [
      ButtonStyleComponent(ButtonVariant.contained),
      ButtonColorComponent(ButtonColor.secondary)
    ]);
    // ...
  }
}

در این مثال، تابع `createButton` مانند یک کارخانه کوچک عمل می‌کند که با گرفتن چند پارامتر، یک موجودیت دکمه کامل را مونتاژ و به دنیا اضافه می‌کند.

ساخت دینامیک موجودیت‌ها

علاوه بر ساخت موجودیت‌ها در زمان راه‌اندازی، اغلب نیاز داریم که در زمان اجرا نیز موجودیت‌های جدیدی خلق کنیم (مثلاً شلیک یک گلوله یا ظاهر شدن یک دشمن). این کار معمولاً در یک `System` انجام می‌شود. 


class SpawnerSystem extends System {
  // ...
  void _spawn(Entity spawnerEntity, SpawnerComponent spawner) {
    // spawner.prefab یک تابع است که یک موجودیت جدید با آرکیتایپ مشخص می‌سازد
    final newEntity = spawner.prefab(); 
    world.addEntity(newEntity);
  }
}

// تعریف یک موجودیت spawner
world.createSpawner(
  prefab: () {
    final entity = Entity();
    archerArchetype.apply(entity); // استفاده از آرکیتایپ برای ساخت سریع
    return entity;
  },
  frequency: Frequency.every(Duration(seconds: 5)),
);

مقایسه با Factory Pattern

آرکیتایپ‌ها و اسمبلرها در Nexus، نسخه ECS از الگوی طراحی Factory هستند. اما یک تفاوت کلیدی وجود دارد: در OOP، یک Factory یک نمونه از یک کلاس را برمی‌گرداند. در ECS، یک اسمبلر یک موجودیت را با ترکیب کامپوننت‌های مختلف مونتاژ می‌کند. این رویکرد بسیار انعطاف‌پذیرتر است، زیرا شما می‌توانید آرکیتایپ‌ها را در زمان اجرا با هم ترکیب کرده و انواع بی‌نهایت متنوعی از موجودیت‌ها را بسازید، بدون اینکه نیاز به تعریف کلاس‌های جدید داشته باشید.
