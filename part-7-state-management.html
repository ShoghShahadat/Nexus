بخش ۷: الگوهای مدیریت وضعیت

بررسی الگوهای پیشرفته برای مدیریت وضعیت‌های پیچیده UI، با تمرکز بر صفحه پروفایل.

فراتر از داده‌های ساده

تا کنون، ما با کامپوننت‌هایی کار کرده‌ایم که داده‌های نسبتاً ساده‌ای را نگهداری می‌کردند (مانند یک `String` برای عنوان). اما در دنیای واقعی، وضعیت‌ها اغلب پیچیده‌تر هستند. یک صفحه ممکن است در حالت‌های مختلفی مانند "در حال بارگذاری"، "موفق"، "خطا" یا "بیکار" باشد. مدیریت این وضعیت‌ها به روشی تمیز و قابل پیش‌بینی، برای ساخت یک تجربه کاربری خوب ضروری است.

در این بخش، ما به سراغ `ProfileModule` می‌رویم تا ببینیم چگونه Nexus این چالش را با استفاده از الگوی ماشین وضعیت (State Machine) حل می‌کند.

صفحه پروفایل: یک مثال عالی از ماشین وضعیت

صفحه پروفایل در اپلیکیشن ما می‌تواند در چهار وضعیت مجزا قرار داشته باشد:

  1. Idle (بیکار): حالت اولیه، که در آن یک دکمه برای شروع دریافت اطلاعات نمایش داده می‌شود.
  2. Loading (در حال بارگذاری): پس از کلیک روی دکمه، یک نشانگر چرخان نمایش داده می‌شود.
  3. Success (موفق): در صورت دریافت موفق اطلاعات، پروفایل کاربر نمایش داده می‌شود.
  4. Error (خطا): در صورت بروز مشکل، یک پیام خطا به همراه دکمه تلاش مجدد نمایش داده می‌شود.

برای مدل‌سازی این وضعیت‌ها، ما از یک کامپوننت داده به نام `ApiStatusComponent` استفاده می‌کنیم. 


// File: lib/src/shared/shared_module.dart (بخشی از پکیج اصلی nexus)

enum ApiStatus { idle, loading, success, error }

class ApiStatusComponent extends Component with SerializableComponent {
  final ApiStatus status;
  final String? errorMessage;

  // ... toJson, fromJson, props
}

این کامپوننت به تنهایی وضعیت فعلی را توصیف می‌کند. یک موجودیت (`profile_page`) این کامپوننت را خواهد داشت و مقدار `status` آن، وضعیت کلی صفحه را تعیین می‌کند.

`ProfileSystem`: منطق تغییر وضعیت

کلاس `ProfileSystem` مسئول مدیریت منطق و تغییر وضعیت‌هاست. این سیستم به رویداد `FetchProfileDataEvent` گوش می‌دهد. 


// File: lib/src/profile/profile_module.dart

class ProfileSystem extends System {
  // ...
  @override
  void onAddedToWorld(NexusWorld world) {
    super.onAddedToWorld(world);
    listen(_onFetchProfile);
  }

  void _onFetchProfile(FetchProfileDataEvent event) async {
    final profileEntity = /* ... پیدا کردن موجودیت پروفایل ... */;

    // 1. تغییر وضعیت به Loading
    profileEntity.add(ApiStatusComponent(status: ApiStatus.loading));
    
    // 2. شبیه‌سازی تماس با API
    await Future.delayed(Duration(milliseconds: 1500));

    // 3. شبیه‌سازی نتیجه موفق یا ناموفق
    if (Random().nextBool()) {
      // SUCCESS: افزودن داده و تغییر وضعیت به Success
      profileEntity.add(ProfileDataComponent(...));
      profileEntity.add(ApiStatusComponent(status: ApiStatus.success));
    } else {
      // FAILURE: تغییر وضعیت به Error
      profileEntity.add(ApiStatusComponent(
        status: ApiStatus.error,
        errorMessage: "خطا در برقراری ارتباط با سرور.",
      ));
    }
  }
}

`StateWidgetAssembler`: انتخاب بیلدر مناسب در UI

حالا که منطق و داده وضعیت را داریم، چگونه به UI بگوییم که برای هر وضعیت، ویجت متفاوتی را رندر کند؟ پاسخ در یک نوع بیلدر خاص به نام `StateWidgetAssembler` نهفته است.

در فایل `main.dart`، ما این اسمبلر را به این صورت پیکربندی می‌کنیم: 


// File: lib/main.dart

final profilePanelBuilder = StateWidgetAssembler(
  builderProvider: (apiStatusComponent) {
    // 1. وضعیت فعلی را از کامپوننت می‌خواند
    final status = apiStatusComponent?.status ?? ApiStatus.idle;
    
    // 2. بر اساس وضعیت، بیلدر مناسب را برمی‌گرداند
    switch (status) {
      case ApiStatus.loading:
        return ProfileLoadingStateBuilder();
      case ApiStatus.success:
        return ProfileSuccessStateBuilder();
      case ApiStatus.error:
        return ProfileErrorStateBuilder();
      case ApiStatus.idle:
        return ProfileIdleStateBuilder();
    }
  },
);

این کد به زیبایی منطق نمایش را از منطق وضعیت جدا می‌کند. `StateWidgetAssembler` به طور خودکار به تغییرات `ApiStatusComponent` گوش می‌دهد و هر بار که وضعیت تغییر می‌کند، تابع `builderProvider` را دوباره اجرا کرده و بیلدر جدید را برای رندر کردن انتخاب می‌کند. هر کدام از این `...StateBuilder` ها یک `IWidgetBuilder` هستند که فقط مسئول رندر کردن یک وضعیت خاص می‌باشند.
