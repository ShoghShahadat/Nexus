بخش ۴۰: غواصی عمیق در TimerComponent

چگونه منطق‌های زمان‌بندی شده را به صورت اعلامی و جدا از سیستم‌های دیگر مدیریت کنیم.

فلسفه وجودی: جداسازی منطق از زمان

در بسیاری از معماری‌ها، منطق‌های زمان‌بندی شده (مانند "بعد از ۵ ثانیه این کار را انجام بده") مستقیماً در دل متدهای دیگر با استفاده از `Future.delayed` یا `Timer.periodic` پیاده‌سازی می‌شوند. این کار، منطق اصلی را با دغدغه‌های زمان‌بندی مخلوط کرده و تست‌پذیری را دشوار می‌سازد.

فلسفه Nexus این است که "زمان‌بندی" خود یک داده است. `TimerComponent` به شما اجازه می‌دهد تا یک "درخواست زمان‌بندی" را به عنوان داده به یک موجودیت اضافه کنید. سپس `TimerSystem`، که یک سیستم عمومی و کاملاً جداست، مسئولیت اجرای این زمان‌بندی را بر عهده می‌گیرد.

کالبدشکافی `TimerComponent` و `TimerTask`

`TimerComponent` یک نگهدارنده برای لیستی از `TimerTask`ها است. هر `TimerTask` یک عملیات زمان‌بندی شده را تعریف می‌کند. 


// از پکیج nexus

class TimerTask with EquatableMixin {
  final String id; // شناسه یکتا برای این تسک
  final double duration; // مدت زمان به ثانیه
  final bool repeats; // آیا باید تکرار شود؟
  
  // رویدادی که در هر فریم تا زمان اتمام تسک، منتشر می‌شود
  final dynamic onTickEvent; 
  
  // رویدادی که دقیقاً پس از اتمام زمان، منتشر می‌شود
  final dynamic onCompleteEvent; 
  
  double elapsedTime = 0.0; // زمان سپری شده، توسط TimerSystem مدیریت می‌شود
}

class TimerComponent extends Component {
  final List tasks;
}

این ساختار به شما اجازه می‌دهد تا چندین عملیات زمان‌بندی شده را به صورت همزمان روی یک موجودیت مدیریت کنید.

`TimerSystem`: موتور زمان

`TimerSystem` یک سیستم مبتنی بر حلقه `update` است که در هر فریم، تمام موجودیت‌های دارای `TimerComponent` را پیدا می‌کند. سپس برای هر `TimerTask`:

  1. مقدار `dt` را به `elapsedTime` اضافه می‌کند.
  2. اگر `onTickEvent` تعریف شده باشد، آن را در `EventBus` منتشر می‌کند.
  3. اگر `elapsedTime` از `duration` بیشتر یا مساوی شود:
    • رویداد `onCompleteEvent` را در `EventBus` منتشر می‌کند.
    • اگر `repeats` برابر `true` باشد، `elapsedTime` را ریست می‌کند.
    • در غیر این صورت، تسک را از لیست حذف می‌کند.
  4. اگر لیست تسک‌ها خالی شود، کل `TimerComponent` را از موجودیت حذف می‌کند.

مثال: ماشین وضعیت انیمیشن دکمه

این الگو همان چیزی است که در بخش ۱۲ برای انیمیشن چندمرحله‌ای دکمه‌ها استفاده کردیم. هر مرحله از انیمیشن، با افزودن یک `TimerTask` جدید، گذار به مرحله بعدی را زمان‌بندی می‌کرد. 


// در ButtonInteractionSystem

void _onShowStatus(ShowStatusEvent event) {
  final entity = world.entities[event.entityId]!;
  
  // ... منطق نمایش وضعیت ...

  final timerComp = entity.get()!;
  timerComp.tasks.clear();
  timerComp.tasks.add(TimerTask(
    id: 'status_to_random',
    duration: 1.5,
    // پس از ۱.۵ ثانیه، این رویداد را برای رفتن به مرحله بعد منتشر کن
    onCompleteEvent: RandomizeStateEvent(entity.id),
  ));
  entity.add(timerComp);
}

مقایسه با `Future.delayed`

استفاده از `TimerComponent` به جای `Future.delayed` چندین مزیت دارد:

  • وابستگی به حلقه بازی: تایمرها با حلقه بازی `NexusWorld` همگام هستند. اگر بازی متوقف (pause) شود، تایمرها نیز متوقف می‌شوند. `Future.delayed` مستقل از حلقه بازی کار می‌کند.
  • داده-محور و قابل بازرسی: شما می‌توانید با مشاهده `TimerComponent` یک موجودیت، دقیقاً ببینید چه تسک‌هایی در صف اجرا هستند و چقدر از زمانشان سپری شده است. این کار دیباگ کردن را بسیار آسان می‌کند.
  • تست‌پذیری: شما می‌توانید `TimerSystem` را در تست‌ها با یک نسخه شبیه‌سازی شده جایگزین کنید تا زمان را به صورت دستی کنترل کرده و گذار بین حالت‌ها را به راحتی تست نمایید.
