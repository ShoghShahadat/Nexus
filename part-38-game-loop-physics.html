مستندات پروژه-محور Nexus

بخش ۳۸: حلقه بازی و فیزیک

نگاهی به ریتم تپنده دنیای Nexus و نحوه پیاده‌سازی سیستم‌های مبتنی بر زمان.

ریتم تپنده: حلقه `update`

قلب هر اپلیکیشن real-time (مانند بازی یا شبیه‌سازی)، یک حلقه بی‌نهایت است که به آن "حلقه بازی" یا "Game Loop" می‌گویند. این حلقه مسئولیت به‌روزرسانی وضعیت دنیا و رندر کردن آن بر روی صفحه را با سرعت بالا (معمولاً ۶۰ بار در ثانیه) بر عهده دارد.

در Nexus، این حلقه توسط `NexusManager` (چه در حالت تک‌تردی و چه در حالت ایزولیت) مدیریت می‌شود. این مدیر از یک `Ticker` فلاتر استفاده می‌کند تا در هر فریم، متد `world.update(dt)` را فراخوانی کند.

`dt` یا Delta Time: کلید حرکت روان

پارامتر `dt` (دلتا تایم) که به متد `update` سیستم‌ها پاس داده می‌شود، یکی از مهم‌ترین مفاهیم در توسعه real-time است. `dt` مدت زمان سپری شده (به ثانیه) از فریم قبلی تا فریم فعلی را نشان می‌دهد.

چرا این مهم است؟ چون نرخ فریم (FPS) دستگاه‌های مختلف ممکن است متفاوت باشد (یکی ۶۰ FPS، دیگری ۱۲۰ FPS). اگر ما حرکت را بر اساس فریم محاسبه کنیم (مثلاً `pos.x += 1`)، کاراکتر ما روی دستگاه ۱۲۰ FPS دو برابر سریع‌تر حرکت خواهد کرد!

با استفاده از `dt`، ما حرکت را مبتنی بر زمان واقعی می‌کنیم و از این مشکل جلوگیری می‌کنیم. 


// حرکت مبتنی بر فریم (بد)
// speed = 1 pixel per frame
position.x += 1;

// حرکت مبتنی بر زمان (خوب)
// speed = 60 pixels per second
// On a 60 FPS device, dt ≈ 1/60, so position.x += 60 * (1/60) => position.x += 1
// On a 120 FPS device, dt ≈ 1/120, so position.x += 60 * (1/120) => position.x += 0.5
// در هر دو حالت، کاراکتر در یک ثانیه، ۶۰ پیکسل جابجا می‌شود.
position.x += speed * dt;

سیستم‌های فیزیکی: نمونه‌های کلاسیک

با داشتن حلقه `update` و `dt`، ما می‌توانیم انواع سیستم‌های فیزیکی را به راحتی پیاده‌سازی کنیم.

`PhysicsSystem`

این ساده‌ترین سیستم فیزیکی است که فقط سرعت را به موقعیت اعمال می‌کند. 


class PhysicsSystem extends System {
  @override
  bool matches(Entity entity) => entity.has() && entity.has();

  @override
  void update(Entity entity, double dt) {
    final pos = entity.get()!;
    final vel = entity.get()!;
    pos.x += vel.x * dt;
    pos.y += vel.y * dt;
    entity.add(pos);
  }
}

`GravitySystem`

این سیستم یک نیروی ثابت (جاذبه) را به سرعت عمودی تمام موجودیت‌هایی که جرم دارند، اعمال می‌کند. 


class GravitySystem extends System {
  final double gravityForce = 9.8;

  @override
  bool matches(Entity entity) => entity.has() && entity.has();

  @override
  void update(Entity entity, double dt) {
    final vel = entity.get()!;
    vel.y += gravityForce * dt; // اعمال نیروی جاذبه به سمت پایین
    entity.add(vel);
  }
}

قدرت ترکیب‌پذیری در عمل

حالا جادوی ECS را ببینید. اگر یک موجودیت فقط `PositionComponent` و `VelocityComponent` داشته باشد، `PhysicsSystem` آن را حرکت می‌دهد. اگر ما `MassComponent` را هم به آن اضافه کنیم، `GravitySystem` نیز شروع به کار روی آن می‌کند و موجودیت ما شروع به سقوط می‌کند! ما قابلیت "سقوط کردن" را به موجودیت اضافه کردیم، بدون اینکه هیچ کدی را در `PhysicsSystem` یا کلاس موجودیت تغییر دهیم. این همان قدرت ترکیب‌پذیری است.
