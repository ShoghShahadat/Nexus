مستندات پروژه-محور Nexus

بخش ۶: گذرگاه رویداد (EventBus)

یادگیری ارتباط غیروابسته (Decoupled) بین ماژول‌ها و سیستم‌ها برای ساخت کدی تمیزتر.

مشکل: وابستگی مستقیم

تصور کنید در اپلیکیشن ما، `DrawerModule` (منوی کناری) نیاز دارد به `AppBarModule` بگوید که عنوان صفحه را تغییر دهد. یک راه حل ساده این است که `DrawerSystem` یک رفرنس مستقیم به `AppBarSystem` داشته باشد و متد `updateTitle` آن را فراخوانی کند.

این روش در پروژه‌های کوچک کار می‌کند، اما با رشد اپلیکیشن، به سرعت به یک "کلاف سردرگم" از وابستگی‌های مستقیم تبدیل می‌شود. ماژول‌ها استقلال خود را از دست می‌دهند و تغییر در یک بخش، نیازمند تغییرات گسترده در بخش‌های دیگر می‌شود. این دقیقاً همان چیزی است که می‌خواهیم از آن اجتناب کنیم.

راه حل: ارتباط از طریق رویدادها

فریم‌ورک Nexus از یک الگوی قدرتمند به نام EventBus (گذرگاه رویداد) برای حل این مشکل استفاده می‌کند. `EventBus` یک کانال ارتباطی مرکزی است. به جای اینکه ماژول‌ها مستقیماً با هم صحبت کنند، یک ماژول یک "رویداد" (Event) را در این کانال "منتشر" (fire) می‌کند و ماژول‌های دیگر که به آن نوع رویداد "علاقه‌مند" هستند، آن را "دریافت" (listen) می‌کنند.

جریان ارتباط با EventBus

DrawerSystem → NavigationItemTappedEvent → EventBus → AppBarSystem

در این مدل، `DrawerSystem` هیچ اطلاعی از وجود `AppBarSystem` ندارد و بالعکس. آن‌ها فقط `EventBus` و نوع رویداد را می‌شناسند.

قدم اول: تعریف یک رویداد

یک رویداد، یک کلاس داده ساده است که اطلاعات مربوط به یک اتفاق را در خود حمل می‌کند. در پروژه ما، وقتی روی یک آیتم در منو کلیک می‌شود، رویداد `NavigationItemTappedEvent` ساخته می‌شود. 


// File: lib/src/shared/shared_module.dart

// این یک کلاس داده ساده (POCO) است.
class NavigationItemTappedEvent {
  final String itemId;
  final String title;

  NavigationItemTappedEvent({required this.itemId, required this.title});
}

قرار دادن رویدادهای مشترک در `SharedModule` یک عمل خوب است تا از وابستگی‌های چرخه‌ای بین ماژول‌ها جلوگیری شود.

قدم دوم: انتشار (Fire) یک رویداد

در لایه UI، زمانی که کاربر روی یک آیتم کلیک می‌کند، ما این رویداد را می‌سازیم و به دنیای منطق ارسال می‌کنیم. 


// File: lib/src/drawer/navigation_panel_builder.dart -> onTap callback

onTap: () {
  // 1. یک نمونه از رویداد را با داده‌های لازم می‌سازیم
  final event = NavigationItemTappedEvent(
    itemId: item.id,
    title: item.label,
  );
  // 2. آن را از طریق manager به EventBus در دنیای منطق ارسال می‌کنیم
  renderingSystem.manager!.send(event);
}

قدم سوم: گوش دادن (Listen) به رویداد

حالا سیستم‌هایی که به این اتفاق اهمیت می‌دهند، می‌توانند به آن گوش دهند. ما این کار را در متد `onAddedToWorld` سیستم انجام می‌دهیم. 


// File: lib/src/app_bar/app_bar_module.dart -> class AppBarSystem

@override
void onAddedToWorld(NexusWorld world) {
  super.onAddedToWorld(world);
  // متد listen به صورت خودکار اشتراک را مدیریت می‌کند
  listen((event) {
    // منطق ما در اینجا اجرا می‌شود
    final appBarEntity = /* ... */;
    appBarEntity.add(AppBarComponent(title: event.title));
  });
}

به همین سادگی! `AppBarSystem` بدون اینکه بداند چه کسی یا چه چیزی این رویداد را فرستاده، به آن واکنش نشان می‌دهد. `BodySystem` نیز به همین رویداد گوش می‌دهد تا محتوای اصلی صفحه را تغییر دهد. این قدرت واقعی ارتباطات غیروابسته است.
