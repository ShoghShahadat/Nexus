بخش ۲۱: موضوع پیشرفته - غواصی در سریال‌سازی

بررسی تفاوت‌ها و کاربردهای سریال‌سازی JSON و باینری در فریم‌ورک Nexus.

سریال‌سازی: زبان مشترک سیستم‌ها

سریال‌سازی (Serialization) فرآیند تبدیل یک شیء در حافظه (مانند یک نمونه از کلاس کامپوننت) به یک فرمت قابل انتقال یا ذخیره‌سازی (مانند رشته JSON یا آرایه‌ای از بایت‌ها) است. این فرآیند برای ارتباط بین ایزولیت‌ها، ذخیره‌سازی داده‌ها و ارتباطات شبکه ضروری است. Nexus دو رویکرد اصلی برای سریال‌سازی ارائه می‌دهد.

۱. سریال‌سازی JSON با `SerializableComponent`

این رویکردی است که تاکنون با آن کار کرده‌ایم. با افزودن `with SerializableComponent` به یک کامپوننت، ما متعهد می‌شویم که متدهای `toJson` و `fromJson` را پیاده‌سازی کنیم. 


class MyComponent extends Component with SerializableComponent {
  final int value;

  MyComponent(this.value);

  @override
  Map toJson() => {'value': value};

  factory MyComponent.fromJson(Map json) {
    return MyComponent(json['value']);
  }
  // ...
}

کاربردها:

  • ارتباط با UI: برای ارسال `RenderPacket`ها از ایزولیت منطق به UI.
  • ذخیره‌سازی: برای ذخیره وضعیت موجودیت‌ها در `SharedPreferences` یا فایل‌های JSON.
  • دیباگ کردن: فرمت JSON خوانا و قابل فهم برای انسان است.

`ComponentFactoryRegistry`: کارخانه بازسازی

وقتی `FlutterRenderingSystem` یک `RenderPacket` دریافت می‌کند، فقط نام کامپوننت (مثلاً `"MyComponent"`) و داده JSON آن را دارد. چگونه می‌فهمد که کدام کانستراکتور `fromJson` را باید فراخوانی کند؟ پاسخ در `ComponentFactoryRegistry` است.

در ابتدای برنامه (در فایل `main.dart`)، ما تمام کامپوننت‌های سریالایزبل خود را در این رجیستری ثبت می‌کنیم. 


// File: lib/src/bootstrap.dart

void registerLayoutKitComponents() {
  final registry = ComponentFactoryRegistry.I;
  registry.register('AppBarComponent', (json) => AppBarComponent.fromJson(json));
  // ... ثبت سایر کامپوننت‌ها
}

این رجیستری یک نقشه از نام کامپوننت به تابع سازنده آن نگه می‌دارد و به فریم‌ورک اجازه می‌دهد تا به صورت پویا کامپوننت‌ها را از داده‌های JSON بازسازی کند.

۲. سریال‌سازی باینری با `BinaryComponent`

سریال‌سازی JSON خوانا است، اما کارآمدترین فرمت نیست. برای ارتباطات شبکه که هر بایت اهمیت دارد (مانند بازی‌های آنلاین)، استفاده از یک فرمت باینری فشرده بسیار بهتر است. Nexus این قابلیت را از طریق `BinaryComponent` فراهم می‌کند. 


// از پکیج nexus

class PositionComponent extends Component with SerializableComponent, BinaryComponent {
  double x, y;
  // ...

  @override
  int get typeId => 1; // شناسه عددی منحصر به فرد برای این کامپوننت

  @override
  void toBinary(BinaryWriter writer) {
    writer.writeDouble(x);
    writer.writeDouble(y);
  }

  @override
  void fromBinary(BinaryReader reader) {
    x = reader.readDouble();
    y = reader.readDouble();
  }
  // ...
}

کاربردها:

  • ارتباطات شبکه (Networking): برای ارسال وضعیت بازی بین سرور و کلاینت‌ها با حداقل پهنای باند.
  • ذخیره‌سازی با حجم کم: برای ذخیره فایل‌های save بازی به صورت فشرده.

همانند `ComponentFactoryRegistry`، یک `BinaryComponentFactory` نیز وجود دارد که شناسه‌های عددی کامپوننت‌ها را به توابع سازنده آن‌ها نگاشت می‌کند.

کدام را انتخاب کنیم؟

برای اکثر اپلیکیشن‌های UI-محور، سریال‌سازی JSON کاملاً کافی و مناسب است. فقط زمانی به سراغ سریال‌سازی باینری بروید که عملکرد شبکه یا حجم فایل ذخیره‌سازی یک دغدغه اصلی باشد. یک کامپوننت می‌تواند هر دو mixin را پیاده‌سازی کند تا در سناریوهای مختلف قابل استفاده باشد.
