مستندات پروژه-محور Nexus

بخش ۲۸: مفهوم پیشرفته - دنیا به عنوان ماژول

یک الگوی معماری سطح بالا برای ساخت "سوپر-اپلیکیشن‌ها" با چندین دنیای مستقل.

الگوی "جهان‌های تودرتو"

تاکنون، ما با یک `NexusWorld` واحد به عنوان مرکز کل اپلیکیشن کار کرده‌ایم. این رویکرد برای اکثر پروژه‌ها کاملاً مناسب است. اما برای اپلیکیشن‌های بسیار بزرگ و پیچیده (که گاهی به آن‌ها "سوپر-اپلیکیشن" گفته می‌شود)، ممکن است حتی یک دنیای واحد نیز بیش از حد بزرگ و پیچیده شود.

در اینجاست که یک الگوی معماری پیشرفته‌تر مطرح می‌شود: در نظر گرفتن خود `NexusWorld` به عنوان یک ماژول.

سناریو: یک اپلیکیشن ویرایشگر

تصور کنید در حال ساخت یک اپلیکیشن ویرایشگر گرافیکی پیچیده مانند Figma یا Photoshop هستید. این اپلیکیشن ممکن است از چندین بخش کاملاً مجزا تشکیل شده باشد:

  • بخش رابط کاربری اصلی (Shell): شامل منوها، نوار ابزار، پنل لایه‌ها و مدیریت کلی فایل‌ها.
  • بخش بوم نقاشی (Canvas): جایی که کاربر اشکال را ترسیم و ویرایش می‌کند. این بخش منطق‌های بسیار پیچیده‌ای برای رندرینگ، محاسبات هندسی و تعاملات کاربر دارد.
  • بخش پلاگین‌ها (Plugins): هر پلاگین می‌تواند یک ویژگی کاملاً جدید با منطق و UI خاص خود اضافه کند.

مدیریت تمام این منطق‌ها در یک `NexusWorld` واحد می‌تواند چالش‌برانگیز باشد.

راه حل: چندین دنیای مستقل

در این الگو، ما می‌توانیم برای هر بخش اصلی، یک `NexusWorld` کاملاً مستقل ایجاد کنیم.

  • `ShellWorld`: مسئولیت مدیریت UI اصلی، منوها و پنل‌ها را بر عهده دارد. این دنیا ماژول‌هایی مانند `MenuModule`, `ToolbarModule`, `LayersPanelModule` را در خود بارگذاری می‌کند.
  • `CanvasWorld`: یک دنیای کاملاً مجزا که فقط و فقط مسئولیت مدیریت اشیاء روی بوم را دارد. این دنیا شامل سیستم‌های سنگین مانند `RenderingSystem`, `PhysicsSystem`, `GeometrySystem` است.
  • `PluginWorld`: هر پلاگین می‌تواند دنیای کوچک و ایزوله خود را داشته باشد.

این دنیاها می‌توانند از طریق یک `EventBus` سطح بالاتر (که در یک `GetIt` والد ثبت شده) با یکدیگر ارتباط برقرار کنند، اما در غیر این صورت، از وجود یکدیگر بی‌خبر هستند. 


// در یک ویجت سطح بالا

class EditorScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        // ویجت مربوط به دنیای UI اصلی
        Expanded(
          flex: 1,
          child: NexusWidget(
            worldProvider: () => createShellWorld(),
            renderingSystem: ShellRenderingSystem(),
          ),
        ),
        // ویجت مربوط به دنیای بوم نقاشی
        Expanded(
          flex: 4,
          child: NexusWidget(
            worldProvider: () => createCanvasWorld(),
            renderingSystem: CanvasRenderingSystem(),
          ),
        ),
      ],
    );
  }
}

مزایای این الگو

  • ایزولاسیون حداکثری: یک باگ یا مشکل عملکردی در `CanvasWorld` هیچ تأثیری بر روی `ShellWorld` نخواهد داشت.
  • مدیریت حافظه بهتر: می‌توان یک دنیا را به طور کامل از حافظه پاک کرد (مثلاً با بستن یک سند) بدون تأثیر بر سایر بخش‌ها.
  • مقیاس‌پذیری نامحدود: این الگو به شما اجازه می‌دهد تا سیستم‌هایی با پیچیدگی بسیار بالا را به بخش‌های کوچک و قابل مدیریت تقسیم کنید.
  • اجرای موازی واقعی: هر `NexusWorld` می‌تواند در ایزولیت جداگانه خود اجرا شود و از هسته‌های مختلف CPU به صورت همزمان استفاده کند.

اگرچه این الگو برای اکثر اپلیکیشن‌ها ضروری نیست، اما دانستن آن به شما نشان می‌دهد که معماری Nexus تا چه حد می‌تواند برای ساخت سیستم‌های نرم‌افزاری پیچیده و مقیاس‌پذیر، انعطاف‌پذیر باشد.
