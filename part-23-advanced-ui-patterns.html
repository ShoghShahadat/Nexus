مستندات پروژه-محور Nexus

بخش ۲۳: الگوهای پیشرفته UI با CustomPainter

چگونه گرافیک‌های سفارشی و پرفورمنس بالا را با داده‌های دنیای Nexus ترسیم کنیم.

فراتر از ویجت‌های استاندارد

کتابخانه ویجت‌های فلاتر بسیار غنی است، اما گاهی اوقات شما نیاز به ترسیم گرافیک‌های کاملاً سفارشی دارید که با ویجت‌های استاندارد قابل پیاده‌سازی نیستند. در این مواقع، `CustomPainter` به کمک ما می‌آید. `CustomPainter` به شما اجازه می‌دهد تا مستقیماً روی یک بوم (Canvas) نقاشی کنید.

ترکیب `CustomPainter` با معماری Nexus یک الگوی بسیار قدرتمند برای ساخت انیمیشن‌ها، نمودارها، بازی‌های کوچک و هر نوع UI سفارشی دیگر است. در این الگو، دنیای Nexus وضعیت و داده‌های گرافیکی را مدیریت می‌کند و `CustomPainter` فقط مسئولیت ترسیم آن داده‌ها را بر عهده دارد.

الگوی کار با `CustomPainter` در Nexus

بیایید یک مثال ساده را در نظر بگیریم: می‌خواهیم دایره‌ای را روی صفحه بکشیم که موقعیت آن توسط دنیای Nexus کنترل می‌شود.

قدم اول: تعریف کامپوننت داده

ما به کامپوننت‌هایی برای نگهداری داده‌های مورد نیاز برای ترسیم نیاز داریم. `PositionComponent` و یک `CircleStyleComponent` سفارشی برای این کار مناسب هستند. 


// کامپوننت سفارشی برای استایل دایره
class CircleStyleComponent extends Component with SerializableComponent {
  final int color; // e.g., 0xFFFFFFFF
  final double radius;
  // ...
}

// ساخت موجودیت
final myCircleEntity = Entity()
  ..add(PositionComponent(x: 100, y: 100))
  ..add(CircleStyleComponent(color: 0xFF9333EA, radius: 50));

قدم دوم: ساخت `CustomPainter`

`CustomPainter` ما باید داده‌های مورد نیاز خود را در کانستراکتور دریافت کند. این کلاس هیچ اطلاعی از Nexus ندارد و فقط داده‌های خام را می‌گیرد و ترسیم می‌کند. 


class CirclePainter extends CustomPainter {
  final double x;
  final double y;
  final double radius;
  final Color color;

  CirclePainter({required this.x, required this.y, required this.radius, required this.color});

  @override
  void paint(Canvas canvas, Size size) {
    final paint = Paint()..color = color;
    canvas.drawCircle(Offset(x, y), radius, paint);
  }

  @override
  bool shouldRepaint(covariant CirclePainter oldDelegate) {
    // فقط در صورتی دوباره نقاشی کن که داده‌ها تغییر کرده باشند
    return x != oldDelegate.x || y != oldDelegate.y || radius != oldDelegate.radius || color != oldDelegate.color;
  }
}

قدم سوم: ساخت `IWidgetBuilder`

حالا به یک `IWidgetBuilder` نیاز داریم که به عنوان پل عمل کند. این بیلدر به موجودیت ما گوش می‌دهد، داده‌ها را از کامپوننت‌ها استخراج می‌کند و آن‌ها را به `CustomPainter` ما تحویل می‌دهد. 


class CircleBuilder implements IWidgetBuilder {
  @override
  Widget build(BuildContext context, FlutterRenderingSystem rs, EntityId entityId) {
    return EntityWidgetBuilder(
      renderingSystem: rs,
      entityId: entityId,
      builder: (context) {
        // 1. خواندن داده از کامپوننت‌ها
        final pos = rs.get(entityId)!;
        final style = rs.get(entityId)!;

        // 2. ساخت ویجت CustomPaint و پاس دادن داده‌ها
        return CustomPaint(
          painter: CirclePainter(
            x: pos.x,
            y: pos.y,
            radius: style.radius,
            color: Color(style.color),
          ),
          child: SizedBox.expand(), // برای اینکه painter کل فضا را بگیرد
        );
      },
    );
  }
}

چرا این الگو بهینه است؟

ویجت `CustomPaint` بسیار بهینه است. فلاتر فقط زمانی متد `paint` را فراخوانی می‌کند که `shouldRepaint` مقدار `true` برگرداند. از آنجایی که ما داده‌ها را به صورت تغییرناپذیر (immutable) از دنیای Nexus دریافت می‌کنیم، می‌توانیم به راحتی در `shouldRepaint` بررسی کنیم که آیا نیاز به نقاشی مجدد هست یا خیر. این کار از بازрисов‌های غیرضروری جلوگیری کرده و عملکرد انیمیشن‌ها را به حداکثر می‌رساند.

با این الگو، شما می‌توانید هر نوع گرافیک سفارشی را به صورت داده-محور و با عملکرد بالا پیاده‌سازی کنید. دنیای Nexus می‌تواند وضعیت هزاران ذره را در یک بازی مدیریت کند و `CustomPainter` آن‌ها را با سرعت ۶۰ فریم بر ثانیه روی صفحه ترسیم نماید.
