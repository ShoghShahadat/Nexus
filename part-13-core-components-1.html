مستندات پروژه-محور Nexus

بخش ۱۳: کامپوننت‌های هسته‌ای (۱ از ۲)

آشنایی با کامپوننت‌های بنیادی پکیج `nexus` برای ساختار، هویت و چرخه حیات.

ابزارهای بنیادی در جعبه ابزار Nexus

تاکنون، ما بیشتر با کامپوننت‌هایی کار کرده‌ایم که برای پروژه `nexus_layout_kit` به صورت سفارشی ساخته شده بودند. اما قدرت واقعی یک فریم‌ورک در ابزارهای عمومی و قابل استفاده مجددی است که ارائه می‌دهد. پکیج `nexus` مجموعه‌ای غنی از کامپوننت‌های هسته‌ای را فراهم می‌کند که بسیاری از نیازهای رایج در توسعه اپلیکیشن را پوشش می‌دهند.

در این بخش و بخش بعدی، ما به بررسی مهم‌ترین این کامپوننت‌ها خواهیم پرداخت.

`TagsComponent`: هویت‌بخشی ساده و کارآمد

این کامپوننت یکی از پرکاربردترین ابزارها در Nexus است. `TagsComponent` به شما اجازه می‌دهد تا یک یا چند برچسب متنی (tag) را به یک موجودیت اختصاص دهید. این برچسب‌ها برای دسته‌بندی و کوئری زدن موجودیت‌ها استفاده می‌شوند. 


// از پکیج nexus

class TagsComponent extends Component with SerializableComponent {
  final Set tags;
  // ...
  bool hasTag(String tag) => tags.contains(tag);
  void add(String tag) => tags.add(tag);
  void remove(String tag) => tags.remove(tag);
}

// نحوه استفاده:
final playerEntity = Entity()
  ..add(TagsComponent({'player', 'character'}));

// در سیستم‌ها می‌توانیم به راحتی موجودیت بازیکن را پیدا کنیم:
final player = world.entities.values.firstWhere(
  (e) => e.get()?.hasTag('player') ?? false
);

ما از این کامپوننت در `nexus_layout_kit` برای شناسایی موجودیت‌های کلیدی مانند `root`, `app_bar`, `body` و `profile_page` استفاده کرده‌ایم.

`PositionComponent`: موقعیت و ابعاد

همانطور که از نامش پیداست، این کامپوننت داده‌های مربوط به موقعیت (x, y)، ابعاد (width, height) و مقیاس (scale) یک موجودیت را نگهداری می‌کند. این کامپوننت برای هر چیزی که نیاز به رندر شدن در یک موقعیت خاص روی صفحه دارد، ضروری است. 


// از پکیج nexus

class PositionComponent extends Component with SerializableComponent {
  double x;
  double y;
  double width;
  double height;
  double scale;
  // ...
}

// نحوه استفاده:
final enemyEntity = Entity()
  ..add(PositionComponent(x: 150, y: 300, width: 50, height: 50));

`ParentComponent` و `ChildrenComponent`: ایجاد سلسله مراتب

این دو کامپوننت به شما اجازه می‌دهند تا روابط والد-فرزندی بین موجودیت‌ها ایجاد کنید. این قابلیت برای ساخت UIهای تودرتو یا صحنه‌های بازی که در آن اشیاء به هم متصل هستند (مانند تفنگی که در دست بازیکن قرار دارد) بسیار کاربردی است. 


// از پکیج nexus

class ParentComponent extends Component with SerializableComponent {
  final EntityId parentId;
}

class ChildrenComponent extends Component with SerializableComponent {
  final List children;
}

// نحوه استفاده:
final player = Entity();
final sword = Entity()
  ..add(ParentComponent(player.id)); // شمشیر فرزند بازیکن است

player.add(ChildrenComponent([sword.id])); // بازیکن والد شمشیر است

یک `TransformSystem` (که در پکیج `nexus` وجود ندارد اما به راحتی قابل پیاده‌سازی است) می‌تواند از این روابط برای محاسبه موقعیت نهایی فرزندان بر اساس موقعیت والدینشان استفاده کند.

`LifecyclePolicyComponent`: مدیریت چرخه حیات و حافظه

این یکی از مهم‌ترین کامپوننت‌های هسته‌ای برای جلوگیری از نشت حافظه (memory leaks) است. این کامپوننت به `GarbageCollectorSystem` می‌گوید که با یک موجودیت چگونه رفتار کند. 


// از پکیج nexus

class LifecyclePolicyComponent extends Component {
  final bool isPersistent; // آیا این موجودیت باید همیشه بماند؟
  final bool Function(Entity entity) destructionCondition; // شرط حذف شدن
}

// مثال ۱: یک موجودیت دائمی مانند پروفایل کاربر
profileEntity.add(LifecyclePolicyComponent(isPersistent: true));

// مثال ۲: یک گلوله در بازی که پس از ۲ ثانیه باید حذف شود
bulletEntity.add(TimerComponent([
  TimerTask(id: 'lifetime', duration: 2.0, onCompleteEvent: ShouldBeDestroyed())
]));
bulletEntity.add(LifecyclePolicyComponent(
  destructionCondition: (e) => e.has(),
));

یک قانون خوب

تقریباً تمام موجودیت‌های شما باید یک `LifecyclePolicyComponent` داشته باشند. این کار تضمین می‌کند که هر موجودیت یک پایان عمر مشخص دارد و به طور تصادفی در حافظه باقی نمی‌ماند.
