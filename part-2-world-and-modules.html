مستندات پروژه-محور Nexus

بخش ۲: ساختن دنیا و ماژول‌ها

آشنایی با قلب تپنده اپلیکیشن، `NexusWorld`، و نحوه سازماندهی کد با استفاده از ماژول‌ها.

`NexusWorld`: مرکز فرماندهی

هر اپلیکیشن Nexus یک مرکز فرماندهی دارد که به آن `NexusWorld` می‌گوییم. این کلاس مسئول نگهداری و مدیریت تمام موجودیت‌ها، سیستم‌ها و ماژول‌ها است. شما می‌توانید `NexusWorld` را به عنوان "جهان" یا "دنیای" اپلیکیشن خود در نظر بگیرید که همه چیز در آن اتفاق می‌افتد. این کلاس، چسبی است که تمام قطعات معماری ECS را به هم متصل می‌کند.

نقطه شروع: `main.dart`

بیایید به فایل `lib/main.dart` در پروژه `nexus_layout_kit` نگاهی بیندازیم. این فایل، نقطه ورود اپلیکیشن ما و جایی است که دنیای Nexus برای اولین بار خلق می‌شود. 


// File: lib/main.dart

import 'package:flutter/material.dart';
import 'package:nexus/nexus.dart';
// ... سایر import ها

void main() {
  // این توابع کامپوننت‌های سریالایزبل را ثبت می‌کنند تا فریم‌ورک
  // بداند چگونه آن‌ها را از JSON بازسازی کند. بعداً به آن‌ها می‌پردازیم.
  registerCoreComponents();
  registerLayoutKitComponents(); 
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  // ...
}

تا اینجا همه چیز استاندارد است. بخش جالب ماجرا درون ویجت `MyApp` قرار دارد، جایی که ما `NexusWorld` را پیکربندی می‌کنیم.

`NexusApp` و `worldProvider`

به جای استفاده مستقیم از `MaterialApp`، ما از یک ویجت پوششی به نام `NexusApp` استفاده می‌کنیم. این ویجت مسئول مدیریت چرخه حیات `NexusWorld` (شامل اجرا در ایزولیت جداگانه) و برقراری ارتباط بین دنیای منطق و دنیای UI فلاتر است.

مهم‌ترین پارامتر `NexusApp`، پراپرتی `worldProvider` است. این یک تابع است که وظیفه دارد یک نمونه جدید از `NexusWorld` را بسازد و آن را با تمام ماژول‌های مورد نیاز اپلیکیشن پیکربندی کند. 


// File: lib/main.dart -> class MyApp -> build method

return NexusApp(
  // تابع سازنده دنیا که در ادامه تعریف می‌شود
  worldProvider: worldProvider, 
  
  // بیلدر اصلی UI که بعداً بررسی می‌شود
  rootBuilder: scaffoldBuilder, 
  
  theme: ThemeData(...),
);

چرا یک تابع (Provider)؟

استفاده از یک تابع به جای یک نمونه مستقیم از `NexusWorld` به فریم‌ورک اجازه می‌دهد تا در صورت نیاز (مثلاً برای اجرا در یک ایزولیت جداگانه) بتواند دنیای جدیدی را بسازد. این کار انعطاف‌پذیری بالایی را فراهم می‌کند و کدهای شما را برای اجرا در محیط‌های چند-نخی (multi-threaded) آماده نگه می‌دارد.

ماژول‌ها: سازماندهی کد بر اساس ویژگی

حالا به قلب `worldProvider` نگاه کنیم. در اینجا می‌بینیم که چگونه اپلیکیشن ما به بخش‌های منطقی و مجزا به نام ماژول (Module) تقسیم شده است. این یکی از زیباترین جنبه‌های Nexus است. 


// File: lib/main.dart -> class MyApp -> build method

NexusWorld worldProvider() {
  // 1. یک دنیای خالی می‌سازیم
  final world = NexusWorld();

  // 2. ماژول‌های مختلف را یکی یکی بارگذاری می‌کنیم
  world.loadModule(SharedModule());
  world.loadModule(AppBarModule());
  world.loadModule(DrawerModule());
  world.loadModule(BodyModule());
  world.loadModule(SettingsModule());
  world.loadModule(ButtonsModule());
  world.loadModule(ProfileModule());
  world.loadModule(CategoryModule());

  // 3. دنیای پیکربندی شده را برمی‌گردانیم
  return world;
}

هر `world.loadModule(...)` یک ویژگی یا قابلیت مجزا را به اپلیکیشن ما اضافه می‌کند. هر ماژول، مجموعه‌ای از سیستم‌ها، کامپوننت‌ها و موجودیت‌های مرتبط با خود را تعریف می‌کند.

  • `AppBarModule`: تمام منطق و داده‌های مربوط به نوار اپلیکیشن را در خود جای داده است.
  • `DrawerModule`: مسئول منوی کشویی کناری است.
  • `ProfileModule`: منطق مربوط به صفحه پروفایل کاربر را مدیریت می‌کند.

این رویکرد ماژولار به ما اجازه می‌دهد تا کدهای مربوط به هر ویژگی را در یک مکان مشخص نگهداری کنیم. این کار باعث می‌شود که پیدا کردن، تغییر دادن و تست کردن کدها بسیار ساده‌تر شود و تیم‌های مختلف بتوانند به صورت موازی روی ویژگی‌های متفاوت کار کنند بدون اینکه نگران تداخل کدها باشند.

گام بعدی

اکنون که با ساختار کلی دنیا و نحوه سازماندهی آن با ماژول‌ها آشنا شدیم، در بخش بعدی به سراغ آجرهای سازنده این معماری می‌رویم: موجودیت‌ها (Entities) و کامپوننت‌ها (Components). خواهیم دید که این ماژول‌ها در درون خود چگونه داده‌ها را تعریف و مدیریت می‌کنند.
