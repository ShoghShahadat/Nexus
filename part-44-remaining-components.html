مستندات پروژه-محور Nexus

بخش ۴۴: بررسی کامپوننت‌های باقی‌مانده

نگاهی سریع به سایر ابزارهای مفید در جعبه ابزار کامپوننت‌های هسته‌ای Nexus.

ابزارهای تخصصی برای کارهای مشخص

در کنار کامپوننت‌های بنیادی که در بخش‌های قبل بررسی کردیم، پکیج `nexus` شامل چندین کامپوننت تخصصی دیگر نیز هست که برای حل مشکلات خاص طراحی شده‌اند. در این بخش، به صورت خلاصه با چند مورد از مهم‌ترین آن‌ها آشنا می‌شویم.

`AnimationComponent` و `AnimationProgressComponent`

فلسفه وجودی: برای پیاده‌سازی انیمیشن‌های ساده و خطی به روشی اعلامی.

`AnimationComponent` یک انیمیشن را با پارامترهایی مانند `duration` و `curve` تعریف می‌کند. `AnimationSystem` این کامپوننت را پردازش کرده و در هر فریم، یک `AnimationProgressComponent` را با مقدار پیشرفت انیمیشن (عددی بین ۰ و ۱) به‌روز می‌کند. سپس لایه UI می‌تواند از این مقدار برای درون‌یابی (interpolate) مقادیر بصری مانند موقعیت، رنگ یا اندازه استفاده کند. 


// شروع یک انیمیشن محو شدن
myEntity.add(AnimationComponent(
  duration: const Duration(seconds: 1),
  curve: Curves.easeOut,
  onUpdate: (entity, progress) {
    // progress از ۰ به ۱ می‌رود
    entity.add(OpacityComponent(1.0 - progress));
  },
  onComplete: (entity) => world.removeEntity(entity.id),
));

`ClickableComponent`

فلسفه وجودی: جداسازی منطق کلیک از جزئیات پیاده‌سازی UI.

این کامپوننت یک تابع `onTap` را نگهداری می‌کند. یک سیستم عمومی به نام `InputSystem` به رویداد `EntityTapEvent` (که از UI می‌آید) گوش می‌دهد، موجودیت مربوطه را پیدا کرده و تابع `onTap` از `ClickableComponent` آن را فراخوانی می‌کند. این به شما اجازه می‌دهد تا منطق کلیک را در دنیای Nexus تعریف کنید، نه در `onPressed` یک ویجت.

`DecorationComponent`

فلسفه وجودی: تعریف و انیمیشن‌سازی دکوراسیون ویجت‌ها به صورت داده-محور.

این کامپوننت به شما اجازه می‌دهد تا ویژگی‌های بصری مانند رنگ پس‌زمینه (ثابت یا گرادینت) و سایه را به صورت داده تعریف کنید. `DecorationAnimationSystem` می‌تواند به صورت خودکار بین دو `DecorationComponent` انیمیشن ایجاد کند، که برای ساخت انتقال‌های UI زیبا بسیار مفید است.

`BlocComponent`

فلسفه وجودی: ایجاد یک پل ارتباطی برای ادغام با اکوسیستم BLoC.

گاهی اوقات شما یک BLoC/Cubit از قبل نوشته شده دارید و می‌خواهید از آن در دنیای Nexus استفاده کنید. `BlocComponent` یک نمونه از BLoC شما را نگهداری می‌کند. سپس یک سیستم سفارشی به نام `BlocSystem` می‌تواند به `stream` آن BLoC گوش داده و در پاسخ به تغییرات وضعیت، کامپوننت‌های دیگر را در دنیای Nexus به‌روز کند. این یک ابزار قدرتمند برای مهاجرت تدریجی از معماری BLoC به ECS است. 


// یک سیستم سفارشی برای اتصال به CounterCubit
class CounterBridgeSystem extends BlocSystem {
  @override
  void onStateChange(int state) {
    // با هر تغییر در Cubit، کامپوننت Nexus را آپدیت کن
    world.rootEntity.add(CounterStateComponent(state));
  }
}

// ثبت BLoC در GetIt و افزودن سیستم به دنیا
GetIt.I.registerSingleton(CounterCubit());
world.addSystem(CounterBridgeSystem());
