بخش ۱۱: مثال عملی - ماژول دسته‌بندی (۴ از ۴)

پیاده‌سازی منطق حذف (Delete) با استفاده از `Dismissible` و انیمیشن‌های خروج.

حذف آیتم‌ها با یک ژست حرکتی

در آخرین بخش از تحلیل ماژول دسته‌بندی، به سراغ پیاده‌سازی قابلیت حذف آیتم‌ها می‌رویم. ما می‌خواهیم کاربر بتواند با کشیدن (swipe) یک آیتم به سمت چپ، آن را حذف کند. برای این کار از ویجت قدرتمند `Dismissible` در فلاتر استفاده می‌کنیم.

پیاده‌سازی `Dismissible` در لایه UI

در ویجت `_CategoryItemTile`، ما `ListTile` را درون یک `Dismissible` قرار می‌دهیم. 


// File: lib/src/category/category_panel_builder.dart -> _CategoryItemTile

// ...
return Dismissible(
  key: ValueKey('dismissible_${item.id}'),
  background: Container(color: Colors.green, /* ... */),
  secondaryBackground: Container(color: Colors.red, /* ... */),
  
  // این پراپرتی کلیدی است!
  confirmDismiss: (direction) async {
    // 1. تعیین نوع عمل بر اساس جهت کشیدن
    final action = direction == DismissDirection.endToStart ? 'delete' : 'share';

    // 2. ارسال رویداد به دنیای منطق
    renderingSystem.manager?.send(SwipeActionEvent(
      itemId: itemId,
      action: action,
    ));

    // 3. اگر عمل "حذف" بود، به ویجت اجازه می‌دهیم آیتم را از درخت ویجت حذف کند
    if (action == 'delete') {
      onDeleteInitiated(itemId); // این یک callback برای مدیریت UI است
      return true;
    }

    // در غیر این صورت (مثلاً برای share)، آیتم به جای خود برمی‌گردد
    return false;
  },
  child: ListTile(...),
);
// ...

مجدداً، لایه UI هیچ منطق حذفی را پیاده‌سازی نمی‌کند. فقط یک رویداد `SwipeActionEvent` را ارسال می‌کند و منتظر می‌ماند تا دنیای منطق وضعیت را به‌روز کند.

رسیدگی به حذف در `CategorySystem`

`CategorySystem` به رویداد `SwipeActionEvent` گوش می‌دهد. منطق متد `_onSwipe` بسیار جالب است. 


// File: lib/src/category/category_module.dart -> class CategorySystem

void _onSwipe(SwipeActionEvent event) {
  final itemEntity = world.entities[event.itemId];
  if (itemEntity == null) return;

  switch (event.action) {
    case 'delete':
      // به جای حذف فوری موجودیت، یک رویداد دیگر ارسال می‌کنیم!
      world.eventBus.fire(PurgeListItemEvent(event.itemId));
      break;
    case 'share':
      // ...
      break;
  }
}

چرا یک رویداد دیگر؟

این یک الگوی طراحی مهم است. `CategorySystem` فقط مسئول منطق مربوط به "دسته‌بندی‌ها" است. حذف یک آیتم از لیست‌های داده‌ای (`allItems` و `visibleItems`) وظیفه یک سیستم عمومی‌تر به نام `ListStateSystem` است. با ارسال رویداد `PurgeListItemEvent`، `CategorySystem` این وظیفه را به سیستم مسئول واگذار می‌کند و اصل تفکیک مسئولیت‌ها را رعایت می‌کند.

`ListStateSystem` و حذف نهایی داده

`ListStateSystem` (که بخشی از پکیج اصلی Nexus است) به `PurgeListItemEvent` گوش می‌دهد. وقتی این رویداد را دریافت می‌کند، شناسه آیتم مورد نظر را از کامپوننت `ListComponent` در موجودیت مدیر لیست حذف می‌کند.

این تغییر در `ListComponent` باعث می‌شود که `CategoryPanelBuilder` در لایه UI بازسازی شود و آیتم حذف شده دیگر در لیست نمایش داده نشود.

و انیمیشن چطور؟

ممکن است بپرسید پس انیمیشن حذف چه می‌شود؟ در نسخه فعلی کد، ما از یک ترفند ساده در `CategoryPanelBuilder` استفاده کرده‌ایم تا آیتم به صورت بصری حذف شود. اما راه حل بهتر و استاندارد Nexus، استفاده از یک سیستم انیمیشن است.

در یک پیاده‌سازی پیشرفته‌تر، `CategorySystem` به جای ارسال `PurgeListItemEvent`، یک `AnimateOutComponent` به موجودیت اضافه می‌کرد. سپس `ListItemAnimationSystem` این کامپوننت را می‌دید، یک انیمیشن محو شدن (fade) را اجرا می‌کرد و پس از اتمام انیمیشن، رویداد `PurgeListItemEvent` را ارسال می‌کرد. این رویکرد یک تجربه کاربری بسیار روان‌تر را ایجاد می‌کند.

پایان کالبدشکافی `CategoryModule`

تبریک! ما با موفقیت یک ماژول کامل CRUD را در معماری Nexus بررسی کردیم. ما دیدیم که چگونه:

  • داده‌ها با کامپوننت‌ها تعریف می‌شوند.
  • UI داده‌ها را از طریق `FlutterRenderingSystem` می‌خواند.
  • تعاملات کاربر به رویداد تبدیل شده و به دنیای منطق ارسال می‌شوند.
  • سیستم‌ها به رویدادها گوش داده و با تغییر کامپوننت‌ها، وضعیت برنامه را به‌روز می‌کنند.
  • این تغییرات به صورت بهینه به UI بازتاب داده می‌شوند.

در بخش بعدی، به سراغ یک مثال پیشرفته‌تر از منطق در سیستم‌ها خواهیم رفت: انیمیشن‌های پیچیده و چند مرحله‌ای در `ButtonsModule`.
