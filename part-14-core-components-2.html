بخش ۱۴: کامپوننت‌های هسته‌ای (۲ از ۲)

بررسی کامپوننت‌های پیشرفته برای مدیریت وضعیت، داده‌های پویا و ماندگاری.

مدیریت داده و وضعیت‌های پیچیده

در بخش قبل با کامپوننت‌های ساختاری آشنا شدیم. در این بخش، به سراغ کامپوننت‌هایی می‌رویم که برای مدیریت داده‌های پیچیده، وضعیت‌های برنامه و ذخیره‌سازی اطلاعات طراحی شده‌اند. این ابزارها به شما کمک می‌کنند تا منطق‌های سطح بالاتر را به روشی تمیز و داده-محور پیاده‌سازی کنید.

`ApiStatusComponent`: مدیریت وضعیت درخواست‌های شبکه

این کامپوننت که قبلاً در بخش ۷ با آن آشنا شدیم، یک ماشین وضعیت ساده برای عملیات آسنکرون (مانند تماس با API) فراهم می‌کند. این کامپوننت به جای استفاده از چندین متغیر `bool` مانند `isLoading` و `hasError`، وضعیت را در یک `enum` تمیز و قابل مدیریت نگهداری می‌کند. 


// از پکیج nexus

enum ApiStatus { idle, loading, success, error }

class ApiStatusComponent extends Component with SerializableComponent {
  final ApiStatus status;
  final String? errorMessage;
  final int? statusCode;
  // ...
}

// نحوه استفاده در یک سیستم:
void _onFetchData(FetchDataEvent event) {
  final entity = world.entities[event.entityId]!;
  entity.add(ApiStatusComponent(status: ApiStatus.loading));
  
  try {
    // ... call api ...
    entity.add(ApiStatusComponent(status: ApiStatus.success));
  } catch(e) {
    entity.add(ApiStatusComponent(status: ApiStatus.error, errorMessage: e.toString()));
  }
}

`BlackboardComponent`: حافظه پویا برای موجودیت‌ها

گاهی اوقات شما نیاز دارید داده‌هایی را به یک موجودیت اضافه کنید بدون اینکه بخواهید برای هر فیلد کوچک یک کامپوننت جدید تعریف کنید. `BlackboardComponent` یک راه‌حل عالی برای این مشکل است. این کامپوننت یک `Map` را در خود نگه می‌دارد و به عنوان یک "تخته سیاه" یا حافظه موقت برای یک موجودیت عمل می‌کند. 


// از پکیج nexus

class BlackboardComponent extends Component with SerializableComponent {
  // ...
  T? get(String key);
  void set(String key, dynamic value);
  bool has(String key);
  void increment(String key, [num amount = 1]);
}

// نحوه استفاده:
final playerEntity = Entity()
  ..add(BlackboardComponent({
    'score': 0,
    'last_login': '2025-08-25'
  }));

// در یک سیستم:
final blackboard = playerEntity.get()!;
blackboard.increment('score', 10); // score becomes 10
playerEntity.add(blackboard); // Re-add to notify changes

این کامپوننت برای هوش مصنوعی، مدیریت وضعیت‌های پیچیده UI، یا هر جایی که نیاز به ذخیره داده‌های ساختارنیافته دارید، بسیار مفید است.

`HistoryComponent`: قابلیت Undo/Redo

این کامپوننت یک راه‌حل آماده برای پیاده‌سازی قابلیت‌های بازگشت به عقب (Undo) و جلو (Redo) فراهم می‌کند. `HistorySystem` به طور خودکار تغییرات کامپوننت‌های مشخص شده را ردیابی کرده و تاریخچه‌ای از وضعیت آن‌ها را در این کامپوننت ذخیره می‌کند. 


// از پکیج nexus

class HistoryComponent extends Component with SerializableComponent {
  final List>> history;
  final int currentIndex;
  final Set trackedComponents; // نام کامپوننت‌هایی که باید ردیابی شوند
  // ...
  bool get canUndo => currentIndex > 0;
  bool get canRedo => currentIndex < history.length - 1;
}

// نحوه استفاده:
final editorEntity = Entity()
  ..add(TextContentComponent("Hello"))
  ..add(HistoryComponent(
    trackedComponents: {'TextContentComponent'},
  ));

// برای انجام undo:
world.eventBus.fire(UndoEvent(editorEntity.id));

`PersistenceComponent`: ماندگاری داده‌ها

این کامپوننت یک نشانگر است که به `PersistenceSystem` می‌گوید که این موجودیت باید در حافظه دائمی (مانند `SharedPreferences`) ذخیره شود. 


// از پکیج nexus

class PersistenceComponent extends Component with SerializableComponent {
  final String storageKey; // کلید منحصر به فرد برای ذخیره‌سازی
}

// نحوه استفاده:
final settingsEntity = Entity()
  ..add(ThemeSettingsComponent(isDarkMode: true))
  ..add(PersistenceComponent('app_settings'));

وقتی `PersistenceSystem` فعال باشد، به طور خودکار تمام کامپوننت‌های `Serializable` موجودیت `settingsEntity` را با کلید `app_settings` ذخیره کرده و در اجرای بعدی برنامه، آن‌ها را بارگذاری می‌کند. این یک راه بسیار ساده و قدرتمند برای ذخیره تنظیمات کاربر، پیشرفت بازی و سایر داده‌های ماندگار است.
