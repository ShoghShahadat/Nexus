مستندات پروژه-محور Nexus

بخش ۱۲: غواصی عمیق در انیمیشن‌ها

بررسی انیمیشن چند مرحله‌ای دکمه‌ها با استفاده از `TimerComponent` و ماشین وضعیت رویداد-محور.

انیمیشن‌های فراتر از `AnimationComponent`

تا کنون، ما از `AnimationComponent` برای انیمیشن‌های ساده (یکبار اجرا شونده یا تکراری) استفاده کرده‌ایم. اما گاهی نیاز به انیمیشن‌های پیچیده‌تر و چند مرحله‌ای داریم. صفحه دکمه‌ها (`ButtonsModule`) در پروژه ما یک مثال فوق‌العاده از این نوع انیمیشن است.

وقتی روی یک دکمه کلیک می‌کنیم، یک چرخه انیمیشن ۵ مرحله‌ای آغاز می‌شود:

  1. Loading: دکمه به حالت لودینگ می‌رود (۱.۵ ثانیه).
  2. Countdown: یک شمارش معکوس ۳ ثانیه‌ای روی دکمه نمایش داده می‌شود.
  3. Status: نتیجه (موفق/ناموفق) به صورت تصادفی نمایش داده می‌شود (۱.۵ ثانیه).
  4. Randomize: ظاهر دکمه به صورت تصادفی تغییر می‌کند (۱ ثانیه).
  5. Reset: دکمه به حالت اولیه خود بازمی‌گردد.

پیاده‌سازی این منطق با یک `AnimationComponent` تنها غیرممکن است. در عوض، ما از یک ترکیب قدرتمند از `TimerComponent` و یک ماشین وضعیت مبتنی بر رویداد در `ButtonInteractionSystem` استفاده می‌کنیم.

`TimerComponent`: زمان‌بندی اقدامات

`TimerComponent` (که در پکیج اصلی Nexus قرار دارد) به ما اجازه می‌دهد تا وظایفی را برای اجرا پس از یک تأخیر مشخص، زمان‌بندی کنیم. هر `TimerTask` می‌تواند یک رویداد را پس از اتمام، منتشر کند. 


// از پکیج nexus

class TimerTask {
  final String id;
  final double duration; // به ثانیه
  final bool repeats;
  final dynamic onTickEvent; // رویداد در هر فریم
  final dynamic onCompleteEvent; // رویداد در پایان
  // ...
}

class TimerComponent extends Component {
  final List tasks;
  // ...
}

ماشین وضعیت در `ButtonInteractionSystem`

این سیستم یک ماشین وضعیت کامل را با استفاده از رویدادهای داخلی پیاده‌سازی می‌کند. بیایید چرخه را دنبال کنیم:

مرحله ۱: شروع با `ButtonTappedEvent`

همه چیز با کلیک کاربر و ارسال رویداد `ButtonTappedEvent` شروع می‌شود. 


// File: lib/src/components_showcase/buttons/systems/button_interaction_system.dart

void _onButtonTapped(ButtonTappedEvent event) {
  // ...
  // 1. وضعیت دکمه را به لودینگ تغییر می‌دهد
  entity.add(ButtonStateComponent(isLoading: true, isDisabled: true));

  // 2. یک تایمر برای رفتن به مرحله بعد تنظیم می‌کند
  final timerComp = entity.get() ?? TimerComponent([]);
  timerComp.tasks.add(TimerTask(
    id: 'loading_to_timer',
    duration: 1.5,
    onCompleteEvent: StartCountdownEvent(entity.id), // رویداد برای مرحله بعد!
  ));
  entity.add(timerComp);
  // ...
}

مرحله ۲: شمارش معکوس با `StartCountdownEvent`

وقتی تایمر ۱.۵ ثانیه‌ای تمام می‌شود، `TimerSystem` رویداد `StartCountdownEvent` را منتشر می‌کند. `ButtonInteractionSystem` به این رویداد گوش می‌دهد: 


void _onStartCountdown(StartCountdownEvent event) {
  // ...
  // 1. وضعیت لودینگ را غیرفعال می‌کند
  entity.add(ButtonStateComponent(isLoading: false, isDisabled: true));

  // 2. دو تایمر جدید تنظیم می‌کند:
  final timerComp = entity.get()!;
  timerComp.tasks.clear();
  timerComp.tasks.addAll([
    // یکی برای آپدیت متن شمارش معکوس در هر 0.1 ثانیه
    TimerTask(id: 'countdown_updater', duration: 0.1, repeats: true, ...),
    // یکی برای رفتن به مرحله بعد پس از 3 ثانیه
    TimerTask(
      id: 'countdown_finished',
      duration: 3.0,
      onCompleteEvent: ShowStatusEvent(entity.id), // رویداد برای مرحله بعد!
    )
  ]);
  // ...
}

ادامه چرخه...

این الگو تا پایان چرخه ادامه پیدا می‌کند. هر متد `_on...` یک مرحله از ماشین وضعیت است. این متد وضعیت فعلی را تنظیم می‌کند و یک `TimerTask` برای گذار به مرحله بعدی ایجاد می‌کند.

این روش به ما اجازه می‌دهد تا انیمیشن‌ها و منطق‌های حالت-محور (stateful) بسیار پیچیده را به مراحل کوچک، قابل مدیریت و قابل فهم تقسیم کنیم. هر مرحله فقط مسئولیت کار خودش را دارد و از طریق رویدادها، کنترل را به مرحله بعدی واگذار می‌کند.

چرا این الگو قدرتمند است؟

این رویکرد مبتنی بر سیستم و رویداد، منطق پیچیده را از کامپوننت‌های داده جدا نگه می‌دارد. کامپوننت‌های `Button...Component` همچنان داده‌های خالص باقی می‌مانند و تمام هوشمندی در `ButtonInteractionSystem` متمرکز است. این کار باعث می‌شود که هم منطق و هم داده‌ها به صورت مستقل قابل تست و توسعه باشند.
