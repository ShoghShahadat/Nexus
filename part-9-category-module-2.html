بخش ۹: مثال عملی - ماژول دسته‌بندی (۲ از ۴)

خواندن داده از دنیای منطق و نمایش آن در رابط کاربری با `CategoryPanelBuilder`.

نمایش داده‌ها در UI

در بخش قبل، ما داده‌های اولیه دسته‌بندی‌ها را در `NexusWorld` ایجاد کردیم. حالا باید این داده‌ها را بخوانیم و به کاربر نمایش دهیم. این وظیفه بر عهده `CategoryPanelBuilder` است، یک `IWidgetBuilder` تخصصی که مسئول رندر کردن کل صفحه مدیریت دسته‌بندی‌هاست.

خواندن داده از `FlutterRenderingSystem`

اولین قدم در هر `Builder`، پیدا کردن شناسه‌های موجودیت‌های مورد نیاز و خواندن داده‌هایشان از کَش `FlutterRenderingSystem` است. 


// File: lib/src/category/category_panel_builder.dart

class CategoryPanelBuilder implements IWidgetBuilder {
  @override
  Widget build(BuildContext context, FlutterRenderingSystem rs, EntityId entityId) {
    // 1. شناسه موجودیت "مدیر" را با استفاده از تگ پیدا می‌کنیم
    final categoryManagerId = rs
        .getAllIdsWithTag(LayoutBuilderTags.categoryPage)
        .firstOrNull;

    if (categoryManagerId == null) {
      return const Center(child: CircularProgressIndicator());
    }

    // 2. با EntityWidgetBuilder به تغییرات موجودیت مدیر گوش می‌دهیم
    return EntityWidgetBuilder(
      renderingSystem: rs,
      entityId: categoryManagerId,
      builder: (context) {
        // 3. کامپوننت لیست را از کش می‌خوانیم
        final listComp = rs.get(categoryManagerId);
        if (listComp == null) {
          return const Center(child: CircularProgressIndicator());
        }

        // 4. از لیست آیتم‌های "قابل مشاهده" برای ساخت UI استفاده می‌کنیم
        final visibleItems = listComp.visibleItems;

        return Column(
          // ... ساختار UI با استفاده از visibleItems
        );
      },
    );
  }
}

نکته کلیدی در اینجا این است که ما به `visibleItems` از `ListComponent` گوش می‌دهیم، نه `allItems`. این یعنی هر زمان که `ListStateSystem` (که بعداً بررسی می‌کنیم) لیست قابل مشاهده را بر اساس فیلتر یا جستجو تغییر دهد، این ویجت به طور خودکار به‌روزرسانی خواهد شد.

رندر کردن هر آیتم با `_CategoryItemTile`

برای نمایش هر آیتم در لیست، ما از یک ویجت جداگانه به نام `_CategoryItemTile` استفاده می‌کنیم. این ویجت نیز از `EntityWidgetBuilder` استفاده می‌کند تا فقط به تغییرات آیتم مربوط به خودش واکنش نشان دهد. 


// File: lib/src/category/category_panel_builder.dart

class _CategoryItemTile extends StatelessWidget {
  // ...
  final EntityId itemId;
  // ...

  @override
  Widget build(BuildContext context) {
    // این ویجت فقط به تغییرات itemId خودش گوش می‌دهد!
    return EntityWidgetBuilder(
      renderingSystem: renderingSystem,
      entityId: itemId,
      builder: (context) {
        // داده‌های خود آیتم را می‌خواند
        final item = renderingSystem.get(itemId);
        if (item == null) return const SizedBox.shrink();

        return ListTile(
          title: Text(item.name),
          subtitle: Text(item.description),
          // ... دکمه‌های ویرایش و حذف
        );
      },
    );
  }
}

اهمیت بازسازی دانه‌ریز (Fine-grained Rebuilding)

این الگو بسیار قدرتمند است. وقتی عنوان یک دسته‌بندی تغییر می‌کند، فقط `EntityWidgetBuilder` مربوط به آن `_CategoryItemTile` خاص بازسازی می‌شود. کل لیست، سایر آیتم‌ها، `AppBar` و بقیه صفحه دست نخورده باقی می‌مانند. این همان راز عملکرد بالای اپلیکیشن‌های Nexus است.

ایجاد تعامل: دکمه "افزودن جدید"

در بالای صفحه، یک دکمه برای افزودن دسته‌بندی جدید وجود دارد. کلیک روی این دکمه، یک دیالوگ را نمایش می‌دهد. 


// File: lib/src/category/category_panel_builder.dart -> build method

// ...
ElevatedButton.icon(
  icon: const Icon(Icons.add),
  label: const Text('افزودن جدید'),
  onPressed: () => _showEditDialog(context, renderingSystem),
),
// ...

متد `_showEditDialog` یک دیالوگ استاندارد فلاتر را با دو فیلد متنی و یک دکمه "ذخیره" نمایش می‌دهد. بخش جالب، اتفاقی است که پس از کلیک روی دکمه "ذخیره" می‌افتد. 


// File: ... -> _showEditDialog -> onPressed of 'Save' button

if (formKey.currentState!.validate()) {
  if (isEditing) {
    // برای ویرایش، یک رویداد Update ارسال می‌شود
    renderingSystem.manager?.send(UpdateCategoryEvent(...));
  } else {
    // برای ساخت، یک رویداد Create ارسال می‌شود
    renderingSystem.manager?.send(CreateCategoryEvent(
      name: nameController.text,
      description: descController.text,
    ));
  }
  Navigator.of(context).pop();
}

همانطور که می‌بینید، لایه UI هیچ منطقی را برای افزودن یا ویرایش آیتم پیاده‌سازی نمی‌کند. وظیفه آن فقط جمع‌آوری داده از کاربر و ارسال یک رویداد به دنیای منطق است. این جداسازی کامل مسئولیت‌ها، کد را بسیار تمیز و قابل نگهداری می‌کند.

در بخش بعدی، خواهیم دید که `CategorySystem` چگونه به این رویدادها گوش می‌دهد و منطق افزودن و ویرایش دسته‌بندی‌ها را پیاده‌سازی می‌کند.
