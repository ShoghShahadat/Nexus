بخش ۲۴: کار با شبکه به صورت عمیق

بررسی دقیق جریان داده در `ApiSystem` و `WebSocketSystem`.

ارتباط با دنیای خارج

در بخش ۲۲ با نحوه تزریق سرویس‌ها آشنا شدیم. اکنون زمان آن است که به صورت عمیق‌تر به سیستم‌های هسته‌ای `ApiSystem` و `WebSocketSystem` نگاه کنیم و ببینیم چگونه از این سرویس‌ها برای مدیریت ارتباطات شبکه به روشی داده-محور و قابل پیش‌بینی استفاده می‌کنند.

`ApiSystem`: مدیریت درخواست‌های REST API

این سیستم برای مدیریت چرخه حیات درخواست‌های HTTP (مانند GET, POST) طراحی شده است. جریان کار با این سیستم کاملاً داده-محور است:

  1. شروع درخواست: شما یک `ApiRequestComponent` به یک موجودیت اضافه می‌کنید. این کامپوننت تمام اطلاعات لازم برای درخواست (URL, method, body) و یک تابع `onParse` را در خود دارد.
  2. تشخیص و اجرا: `ApiSystem` در حلقه `update` خود، موجودیت دارای این کامپوننت را پیدا می‌کند. سپس بلافاصله `ApiRequestComponent` را حذف می‌کند تا از اجرای مجدد آن جلوگیری شود.
  3. تغییر وضعیت به Loading: سیستم یک `ApiStatusComponent` با وضعیت `loading` به موجودیت اضافه می‌کند. این تغییر به UI ارسال شده و باعث نمایش یک نشانگر چرخان می‌شود.
  4. ارسال درخواست: سیستم متد `request` از `INetworkService` ثبت شده را فراخوانی می‌کند.
  5. پردازش پاسخ:
    • در صورت موفقیت: سیستم تابع `onParse` از `ApiRequestComponent` اصلی را با پاسخ JSON فراخوانی می‌کند. این تابع لیستی از کامپوننت‌های داده (مثلاً `ProfileDataComponent`) را برمی‌گرداند. این کامپوننت‌ها به موجودیت اضافه می‌شوند و وضعیت `ApiStatusComponent` به `success` تغییر می‌کند.
    • در صورت خطا: وضعیت `ApiStatusComponent` به `error` تغییر کرده و پیام خطا در آن ذخیره می‌شود.

// شروع یک درخواست در یک سیستم دیگر (مثلاً در پاسخ به یک رویداد کلیک)
void _onButtonClicked(event) {
  final profileEntity = /* ... */;
  profileEntity.add(ApiRequestComponent(
    url: 'https://api.example.com/user/1',
    onParse: (json) {
      // این تابع، JSON را به کامپوننت‌های داده تبدیل می‌کند
      return [ProfileDataComponent.fromJson(json)];
    },
  ));
}

این الگو تضمین می‌کند که تمام منطق شبکه (ارسال، مدیریت وضعیت، پارس کردن) در یک مکان مشخص (`ApiSystem`) متمرکز شده و کاملاً از UI جدا است.

`WebSocketSystem`: ارتباطات Real-time

این سیستم برای ارتباطات دوطرفه و پایدار با سرور از طریق WebSockets طراحی شده است. جریان کار آن مشابه `ApiSystem` اما برای یک اتصال مداوم است.

  1. شروع اتصال: شما یک `WebSocketRequestComponent` به یک موجودیت اضافه می‌کنید. این کامپوننت شامل URL و یک تابع `onParseMessage` است.
  2. برقراری اتصال: `WebSocketSystem` با استفاده از `IWebSocketService` ثبت شده، اتصال را برقرار می‌کند. وضعیت موجودیت با `WebSocketStateComponent` به `connecting` و سپس `connected` تغییر می‌کند.
  3. گوش دادن به پیام‌ها: سیستم به جریان پیام‌های ورودی از سرویس WebSocket گوش می‌دهد.
  4. پارس کردن و به‌روزرسانی: با دریافت هر پیام، سیستم تابع `onParseMessage` را فراخوانی می‌کند. این تابع پیام خام را به لیستی از کامپوننت‌های داده تبدیل کرده و `WebSocketSystem` آن‌ها را به موجودیت مربوطه اضافه می‌کند.
  5. مدیریت قطع اتصال: در صورت قطع شدن اتصال، `WebSocketStateComponent` به‌روز شده و اشتراک (subscription) به جریان پیام‌ها لغو می‌شود.

یکپارچگی با دنیای ECS

زیبایی این دو سیستم در این است که آن‌ها ارتباطات شبکه را به زبان ECS ترجمه می‌کنند. نتیجه یک درخواست API یا یک پیام WebSocket، چیزی جز "افزودن یا به‌روزرسانی کامپوننت‌ها" نیست. این یعنی بقیه سیستم‌های شما (مانند سیستم‌های منطق بازی یا UI) نیازی به دانستن چیزی در مورد شبکه ندارند؛ آن‌ها فقط به تغییرات داده در کامپوننت‌ها واکنش نشان می‌دهند.
