بخش ۸: مثال عملی - ماژول دسته‌بندی (۱ از ۴)

شروع کالبدشکافی یک ماژول کامل CRUD: تعریف داده‌ها و برپایی اولیه.

از تئوری به عمل

در بخش‌های گذشته، با مفاهیم بنیادی ECS آشنا شدیم. اکنون زمان آن رسیده که این مفاهیم را در یک سناریوی واقعی و کامل به کار بگیریم. ماژول `CategoryModule` در پروژه `nexus_layout_kit` یک مثال بی‌نقص است، زیرا تمام عملیات اصلی پایگاه داده یعنی ساخت (Create)، خواندن (Read)، به‌روزرسانی (Update) و حذف (Delete) یا به اختصار CRUD را پیاده‌سازی می‌کند.

در این بخش و سه بخش بعدی، ما این ماژول را به طور کامل تحلیل خواهیم کرد. در این قسمت، بر روی تعریف داده‌ها و ساختار اولیه تمرکز می‌کنیم.

قدم اول: تعریف داده با کامپوننت‌ها

هر ویژگی با تعریف داده‌هایش شروع می‌شود. برای یک "دسته‌بندی"، ما به چه اطلاعاتی نیاز داریم؟ احتمالاً یک شناسه، یک نام و یک توضیح. این دقیقاً همان چیزی است که در `CategoryItemComponent` تعریف شده است. 


// File: lib/src/category/category_module.dart

class CategoryItemComponent extends Component with SerializableComponent {
  final String id;
  final String name;
  final String description;

  CategoryItemComponent({
    required this.id,
    required this.name,
    required this.description,
  });

  // ... toJson, fromJson, props
}

هر موجودیت (Entity) که این کامپوننت را داشته باشد، به عنوان یک آیتم دسته‌بندی شناخته می‌شود.

علاوه بر این، ما به یک کامپوننت دیگر برای مدیریت وضعیت "در حال ویرایش" نیاز داریم. `EditingCategoryComponent` یک کامپوننت نشانگر (Marker Component) است. این کامپوننت هیچ داده‌ای ندارد و صرفاً وجود آن بر روی یک موجودیت، نشان‌دهنده یک وضعیت خاص است. 


// File: lib/src/category/category_module.dart

// این کامپوننت هیچ داده‌ای ندارد.
class EditingCategoryComponent extends Component with SerializableComponent {
  // ...
}

قدم دوم: ساخت موجودیت‌های اولیه

حالا که داده‌ها را تعریف کردیم، باید موجودیت‌های اولیه را بسازیم. این کار در `CategoryEntityProvider` انجام می‌شود. 


// File: lib/src/category/category_module.dart

class CategoryEntityProvider extends EntityProvider {
  @override
  void createEntities(NexusWorld world) {
    // 1. دو آیتم دسته‌بندی اولیه می‌سازیم
    final item1 = Entity()
      ..add(CategoryItemComponent(id: '1', name: 'کتاب‌ها', ...))
      ..add(LifecyclePolicyComponent(isPersistent: true));
    final item2 = Entity()
      ..add(CategoryItemComponent(id: '2', name: 'فیلم‌ها', ...))
      ..add(LifecyclePolicyComponent(isPersistent: true));
    
    world.addEntity(item1);
    world.addEntity(item2);

    // 2. یک موجودیت "مدیر" برای لیست می‌سازیم
    final listManager = Entity()
      ..add(TagsComponent({LayoutBuilderTags.categoryPage}))
      ..add(ListComponent(
        listId: 'categories_list',
        allItems: [item1.id, item2.id],
        visibleItems: [item1.id, item2.id],
      ))
      ..add(ListStateComponent())
      ..add(LifecyclePolicyComponent(isPersistent: true));
      
    world.addEntity(listManager);
  }
}

موجودیت مدیر لیست (List Manager)

این یک الگوی بسیار مهم در Nexus است. به جای اینکه منطق لیست (مانند فیلتر کردن یا مرتب‌سازی) را پخش کنیم، یک موجودیت مرکزی می‌سازیم که مسئولیت مدیریت وضعیت کلی لیست را بر عهده دارد. این موجودیت کامپوننت‌های `ListComponent` (که شناسه‌های تمام آیتم‌ها را نگه می‌دارد) و `ListStateComponent` (که وضعیت فیلتر و مرتب‌سازی را نگه می‌دارد) را در خود دارد.

جمع‌بندی این بخش

تا اینجا، ما ساختار داده‌ای ماژول خود را بنا نهادیم:

  • با `CategoryItemComponent` تعریف کردیم که یک "دسته‌بندی" چیست.
  • با `CategoryEntityProvider`، داده‌های اولیه و یک موجودیت مدیر برای لیست را خلق کردیم.

اکنون که داده‌های ما در `NexusWorld` آماده هستند، در بخش بعدی خواهیم دید که چگونه `CategoryPanelBuilder` این داده‌ها را از `FlutterRenderingSystem` می‌خواند و آن‌ها را به صورت یک لیست قابل تعامل در UI نمایش می‌دهد.
